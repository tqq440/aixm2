## 理解完整链路

**ASR/图片页面或HTTP上传 → API校验和保存输入 → M05同一事务保存任务、幂等及待投递事件 → M08投递 → M07按能力通知 → M12/M14 Worker申请租约 → 受管子进程执行Whisper/YOLO → 数据库保存JSON结果 → 确认通知 → API或页面查询。**

音频或图片文件是输入，任务档案是状态和结果，通知用于提醒 Worker。收到通知仍须申请有效租约，不能直接把重复通知当成新的执行许可。M08 还负责等待超时、执行权到期和有限重试；任务终态、租约与进程是否已经结束各有不同含义。

在线文本的另一条链路为：**页面JSON → M02准确版本与准入 → M13静态实例许可/HTTP生成 → M03 SSE事件 → 页面增量展示 → M13幂等收尾**。只保存生命周期元数据，不保存聊天正文，不借离线重试器重放回答；真实引擎验证仍缺服务。

`modules` 只组织运行入口和生命周期；`controller` 接收 HTTP；`service` 决定业务规则；`data` 负责持久化；`schema` 校验输入输出；`common/utils` 复用基础能力。后台沿用三级目录和绝对导入。
