# ASR调度页面与故障处理（v2.12本机-2C）

本部分在原ASR操作页增加“ASR调度”、目标资源资料和任务选择说明。页面帮助理解平台为什么等待、原任务选了哪个目标；**刷新或展开面板不会选择设备、取得许可或重新提交音频。**本部分已于`2026-10-20T10:23:42+08:00`开发侧交付、待用户验收，实际证据和限制见[本机-2C记录](阶段记录/本机-2C-ASR调度页面与故障说明-验收记录.md)，不把页面显示当作真实GPU/CPU已经接入。

保留原上传、结果查看/下载、ASR服务管理和YOLO/LLM入口，模型启停职责不变。真实新增目标仍禁用，日常仍是原固定目标、设备unknown和限额1。后续真实设备、共享容量和CPU性能须在3A核实，3B再联调。

## 1. 先看“ASR调度”，再看目标资料

进入现有ASR页面，在“ASR调度”区域读取状态；需要时点击“刷新调度信息”，展开“目标与资源报告”。

| 页面显示 | 表示什么 | 不能推断什么 |
|---|---|---|
| 原固定通道 | 未启用新路由，沿用原外部服务配置 | 不能从地址或旧转写成功推断GPU型号/余量 |
| 隔离调度验证 | 配置与调用池满足本轮隔离检查 | 不表示实验室GPU/CPU或真实容量已接通 |
| 调度等待核实 | 路由、隔离条件或本地调用池资料不足，阅读具体原因 | 不表示所有GPU都满载，也不自动转交CPU |
| 调度状态未确认 | 新读取失败、返回格式不完整、快照过期或页面暂不可见 | 不继续把上次绿色/可用样式当作当前状态 |

新增调度状态接口没有available字段，不是远端健康检查。旧调用通道的“调用容量”和新目标资料是两种信息：前者是本平台许可账本，后者是有来源和时效的报告；与GPU利用率、显存及物理空闲不能互相替代。

目标资料展示目标编号、共享组、平台配置限额、设备声明及报告。GPU/CPU显示“声明·待核实”，没有报告时显示“设备余量未知”。target和capacity_group分别表示报告范围，来源和provided/isolated类别明确列出；provided只是提供方资料，isolated是隔离测试，不是“验证通过”。

采样时间和到期时间决定报告时效。新鲜报告里的0是“报告值为0”，null是未知；过期、读取失败或时间异常时数值显示未确认，不用旧数值代表当前资源。多个目标按页读取，不把同一共享组内的目标数量相加当作更多容量。

## 2. 选择一条任务，查看为什么等待

任务详情保留原状态、执行次数、期限、错误和结果区，另显示调度说明。旧固定通道任务没有路由记录时，页面明确说明“未记录GPU/CPU选择”，不会为历史转写补造设备。

| 详情情形 | 如何理解和处理 |
|---|---|
| 等待选择执行目标 | 后台只读解释当前等待原因；展开候选原因，查看设备/资源/槽/CPU条件缺项 |
| 候选满足本次条件 | 只是本次只读评估建议，仍须Worker在原领取事务重新核对、冻结并取得许可 |
| 已选择GPU/CPU目标 | 展示该任务已经冻结的目标和选择时间；设备资料仍须按isolated/provided区分，不代表当前硬件利用率 |
| 原目标结果待核对 | 请求可能已到上游，不能自动重发或转交CPU；结果是否已确认与容量是否经人工释放是两件事 |
| 任务已结束 | 保留原选择或未选择事实，不再改派；失败按原错误说明核对，成功结果仍从原结果区查看/下载 |
| 调度原因未确认 | 详情读取失败或解释过期，先刷新；不要靠重复上传试探设备 |

已选目标的reasonCode保留原选择原因；当前完成、失败或结果未知状态用单独的statusCode/reasonCategory解释，不覆盖历史选择。管理员即使已按原流程释放容量，也不把未知结果改为成功，更不会自动补发请求；实际占位应查看原调用记录。

列表只读取批量保存的选择信息和轻量状态，不逐行评估资源；要看当前等待原因应打开任务详情。等待不会增加执行次数或延长原截止时间，页面也没有改派、启用目标或扩大限额按钮。

## 3. 常见等待与故障

| 提示类型 | 下一步 |
|---|---|
| 设备/兼容性未核实、目录已变化或目标未启用 | 核对目录资料与路由固定修订；真实目标保持禁用，待3A资料齐备，不能仅凭页面改成已验证 |
| 资源、健康、调用槽报告缺失/过期/时间异常 | 等待有效报告或核对本地时钟/调用池，缺信息不能当作设备空闲或GPU满载 |
| 容量已满或保守扣减后余量不足 | 按原期限等待；保守余量不足也未必证明GPU已满，不能据此无条件交给CPU |
| CPU支持/样本缺失、样本过期、规模/并发/耗时预算不符 | 补同模型CPU实证或保留等待；本机Whisper不是外部SenseVoice的CPU替代 |
| 调用池停止、加载中或心跳无法确认 | 核对原本机调用池与进程状态；外部模型部署启停仍由服务方负责 |
| 原请求结果未知 | 沿原人工核对流程处理，不从页面复制任务到另一目标重跑 |
| 调度信息或目标目录读取失败 | 先刷新，核对API是否运行；仅保留上次记录供参考，不宣称当前可用 |

“调度信息读取失败”和“目标目录读取失败”分别显示，单项失败不会把另一项成功响应冒充完整成功；原任务错误区继续承担实际执行错误说明。

页面定时读取本地诊断与目录，隐藏页面时暂停读取，恢复后重新核对；响应快照过期后保守显示未确认，目录报告同时还受各自TTL限制。新的诊断/目录GET不发送上游健康、资源或推理请求，不延长采样有效期，不写数据库。原外部status接口保留原通道逻辑，不能把它与新纯只读诊断混称。
