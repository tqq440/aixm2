## 1. 通用约定

成功响应的格式是：

```json
{"data": {"status": "ok", "database": "ok", "service": "inference-platform"}, "requestId": "一次请求的编号"}
```

失败响应的格式是：

```json
{"error": {"code": "TASK_NOT_FOUND", "message": "任务不存在。", "details": []}, "requestId": "一次请求的编号"}
```

- JSON 字段使用 `camelCase`。客户端以 HTTP 状态码和 `error.code` 判断失败，不依赖中文文案完全不变。
- 参数校验错误的 `details` 列表包含 `field` 与 `code`；不会返回输入中的秘密或后台堆栈。未声明的参数、重复的查询/表单字段会被拒绝。
- 每个响应都有 `X-Request-ID` 响应头，JSON响应中与 `requestId` 相同；图片成功响应是PNG字节，在线创建成功是SSE事件流，均不使用JSON成功外层。请求可自带该头，长度为1—64，首字符为字母或数字，后续允许字母、数字、点、下划线和短横线；不合法时返回422并生成新的可用编号。
- 所有日期为带 UTC 时区的 ISO 8601 字符串；页面转换成本地时间。`null` 表示该阶段尚未发生或当前没有值。
- 响应设置 `Cache-Control: no-store`。任务状态以后台查询结果为准，提交成功只表示任务已经保存。
- 查询参数只接受声明的字段：模型目录接受`taskType`；离线任务列表接受`taskType/page/pageSize`；图片读取接受`variant`；在线请求列表、节点列表和实例会话列表接受`page/pageSize`；实例列表接受`page/pageSize/nodeId`；ASR目标目录接受`offset/limit`。其他接口不接受查询参数。

| 方法与路径 | 成功状态 | 用途 |
|---|---|---|
| `GET /api/health` | 200 | HTTP 与数据库连接检查 |

`{taskId}` 必须是后台生成的 32 位小写十六进制编号。合法但不存在的编号返回 404；格式错误返回 422。

## 2. 健康检查与运行报告

`GET /api/health` 每次实际执行数据库 `SELECT 1`。`data.status`、`data.database` 为 `ok` 只说明 HTTP 与 SQLite 连接正常，不能证明迁移最新、模型完整或 Worker 就绪。

`GET /api/runtime` 的 `data` 包含：

| 字段 | 含义 |
|---|---|
| `observedAt`、`apiStatus` | 本次数据库观察时间、API 状态 `running` |
| `worker`、`visionWorker`、`dispatcher` | 三个组件的报告，结构相同；`worker`保留为ASR，新增`visionWorker`为图片检测 |
| `executionConcurrency` | 配置槽位合计2：ASR与Vision各1；不表示当前两个模型都已就绪 |
| `automaticExecutionRetry` | `true`，表示已实现有限执行重试；不代表自动重启退出的 Worker 父进程 |
| `message` | 当前能力边界说明 |

每个组件包含 `componentId`、`reportedState`、`availability`、`ready`、`modelReady`、`pid`、`childPid`、`activeTaskId`、`heartbeatAt`、`heartbeatAgeSeconds`、`lastError`。`availability` 分别可能为 `not_started`（无报告）、`online`（报告有效）、`stale`（报告过期）、`stopped`（已报告停止）或 `error`（已报告错误）。

两个 Worker 的 `ready=true` 均要求有效心跳、处于空闲状态且模型已加载；忙碌的 Worker 会显示 `ready=false`，不能据此认定故障。组件标识分别为 `worker`、`vision_worker`、`dispatcher`；同一任务的执行者仍有独立运行会话身份，报告不互相覆盖。心跳过期不是进程退出证明，PID 也不是终止任意进程的授权。此接口没有 GPU 利用率、集群容量或进度百分比。

### ASR-2A：节点、实例与会话只读查询

原`/api/runtime`仍读取三个组件当前保存的报告。新增登记档案与它分开：GET不登记、不自动采样、不启动或接管进程。维护步骤见[节点与实例登记说明](节点与实例登记说明.md)。

`GET /api/nodes?page=1&pageSize=20`和`GET /api/instances?page=1&pageSize=20`返回`data.items/total/page/pageSize`。`page`为1—1000000，`pageSize`为1—100；实例列表可用`nodeId`筛选，不存在的合法节点返回404。节点和实例ID均为32位小写十六进制，格式错误422，不存在404；未知字段、重复查询字段及超限分页拒绝。

| 查询数据 | 字段与含义 |
|---|---|
| 节点列表项及节点详情 | `nodeId/hostname/osName/osVersion/architecture/cpuCount`，`registeredAt/metadataObservedAt`；`registrationState=registered`、`agentStatus=not_started/online/offline/stale`、`gpuStatus=not_probed` |
| 实例列表项 | `instanceId/nodeId/instanceKey/modelId/modelVersion/adapterKey/executionDevice/registeredAt`；当前`instanceKey=asr-default`、`executionDevice=cpu`、`registrationState=registered`、`managementMode=legacy_worker/node_agent`、`runtimeState=unknown` |
| 实例详情 | `data.instance`同上；`data.latestObservation`为最近已保存会话观测或null |
| 实例会话列表 | `data.items/total/page/pageSize/evaluatedAt`；`evaluatedAt`为本次计算报告新鲜度的数据库时间 |

节点只返回展示信息，不返回原始MachineGuid或内部身份哈希。逻辑处理器数不是空闲CPU容量；GPU未探测不能解释为没有GPU。登记时间不是模型启动时间，元信息采集时间不是Agent心跳。实例`runtimeState=unknown`是本阶段的保守管理结论，报告内容单独展示。

每条会话观测包含`sessionId/instanceId/source/workerSessionId/workerPid/childPid/reportedState/reportedModelReady/activeTaskId/heartbeatAt/workerStartedAt/observedAt/lastError/freshness/heartbeatAgeSeconds/exitConfirmed`。来源固定为`legacy_worker_observation`，来自维护命令对原ASR Worker报告的显式归档；`sessionId`是档案ID，`workerSessionId`是原Worker实际启动会话ID，不是Agent会话。

| freshness | 含义 |
|---|---|
| `fresh` | 最新已采样会话的心跳尚在配置有效窗口内，只说明报告新鲜 |
| `stale` | 最新已采样心跳已过期，不能推定进程已停止 |
| `superseded` | 已存在更晚启动的会话，本条保留为历史 |
| `clock_skew` | 查询时数据库时间早于报告心跳，年龄为null，不能视作正常就绪 |

默认有效窗口沿用`INFERENCE_RUNTIME_STALE_SECONDS`（15秒）；GET按数据库时间计算，不更新档案。即使原Worker仍在持续报心跳，未再次显式采样的档案也可能过期。`reportedModelReady=true`表示报告当时已加载，忙碌不是未加载；本接口不提供“立即可分配”的实例池。`exitConfirmed`固定false，即便`reportedState=stopped`也不声明已确认退出。这是ASR-2A旧观测契约，ASR-2B的Agent和受管退出从下方独立管理接口查询；仍没有完整集群存活状态机。

接口沿用统一错误外层：`NODE_NOT_FOUND`或`INSTANCE_NOT_FOUND`为404，参数校验为422，数据库/迁移不可用为503 `NODE_REGISTRY_UNAVAILABLE`。登记档案不提供POST/PUT/DELETE写入；新增管理写操作仅使用下方固定start/stop路径，不能发送PID或任意命令。登记冲突、模型绑定及旧报告异常仍由维护命令处理。

### ASR-2B：受控启动、停止和管理查询

本节按当前Controller、Schema和Service记录，真实验收结果见ASR-2B阶段记录。默认只管理本机已登记的一个CPU ASR实例。GET查询不启动模型；启动/停止请求已受理不等于动作完成；`starting`表示已受理启动意图，可能仍等待进程启动或模型加载，此时`workerSessionId`也可以为null。

`GET /api/instances/{instanceId}/management` 返回：

| 字段 | 含义 |
|---|---|
| `instanceId/nodeId/managementMode` | 固定登记身份，管理方式为`node_agent` |
| `state/reportedState/desiredState` | 本次结合新鲜度解释的状态、最后实际报告、`running/stopped`期望；状态可能为stopped/starting/ready/busy/stopping/stop_unconfirmed/failed/unknown |
| `agentAvailable/agentSessionId/agentPid` | Agent报告是否新鲜且未确认关闭、管理会话及PID；PID不作为客户端终止授权 |
| `workerSessionId/childPid` | 本次受管启动及模型子进程；未启动可以为null |
| `commandRevision` | 当前命令修订号；管理POST的`expectedRevision`须与其一致 |
| `modelReady/acceptingTasks/activeTaskId` | 模型是否已加载、是否允许新单及当前任务；busy不等于未加载，stopping可仍在处理当前音频 |
| `heartbeatAt/evaluatedAt` | 最近心跳与本次判定的数据库时间 |
| `exitConfirmedAt/shutdownConfirmedAt` | 当前受管启动的退出确认时间、Agent关闭确认时间；没有证据时为null |
| `lastError` | 最近安全错误摘要，不返回秘密或任意异常堆栈 |

历史`childPid`可以在退出后保留，仅用于追溯，不作为操作该PID的授权。Agent异常死亡遗留未确认会话时当前保守阻断，无自动恢复或清理流程。尚无Agent控制记录时为`unknown`，登记成功不能代替实际启动。报告过期且会话未确认退出时为`unknown`，若停止意图已生效则为`stop_unconfirmed`；不得把心跳过期当成停止成功。`modelReady`、`acceptingTasks`会按新鲜度保守解释。

`GET .../management/sessions?page=1&pageSize=20` 采用既有分页限制，返回`data.items/total/page/pageSize`。每条包含`workerSessionId/instanceId/agentSessionId/agentPid/childPid/state/startedAt/endedAt/exitConfirmedAt/lastError`。这是受管启动尝试历史，旧`/sessions`仍返回`legacy_worker_observation`，不互相覆盖。

固定POST仅接受本机回环连接、正确`X-Management-Token`及JSON：

```json
{"agentSessionId":"0123456789abcdef0123456789abcdef","expectedRevision":0}
```

示例会话ID必须替换为实际ID，修订号也必须使用最新GET值。`expectedRevision`是非负整数，布尔值或字符串不接受；未知/重复参数拒绝。令牌从本地`INFERENCE_AGENT_TOKEN`读取，长度32—256字符，默认未配置；不在此处展示真实值。CLI使用本机维护身份调用同一Service，不需要把令牌粘进命令行。

两个POST均返回202及最新管理状态。相同当前会话/修订下重复请求同一目标安全；若会话或修订已变化，返回409并要求重新查询，不盲目重放旧请求。停止意图与任务受理/通知领取/执行准入按SQLite写事务排序：意图生效后不接受或领取新ASR任务，当前任务沿原租约/超时/取消/提交规则收尾，原排队期限不延长。

| 错误码 | HTTP状态与含义 |
|---|---|
| `AGENT_LOCAL_ONLY` | 403，非本机连接或不是本机实例 |
| `AGENT_TOKEN_NOT_CONFIGURED` | 503，HTTP管理令牌未配置，可使用本机CLI |
| `AGENT_UNAUTHORIZED` | 401，管理令牌缺失或不匹配 |
| `AGENT_COMMAND_STALE` | 409，Agent会话或命令修订已变化 |
| `ASR_AGENT_UNAVAILABLE` | 503，Agent尚未在线或心跳过期 |
| `ASR_STOP_UNCONFIRMED` / `ASR_STOP_IN_PROGRESS` | 409，当前会话未确认退出，不得启动替代实例 |
| `ASR_SERVICE_STOPPED` | 503，新音频提交时ASR未启动或正在停止；旧结果和幂等重放仍可用 |
| `ASR_SERVICE_NOT_READY` | 503，模型尚未就绪，等待加载完成 |
| `ASR_INSTANCE_MODEL_MISMATCH` | 409，请求模型与固定受管实例绑定不同 |

这只是本机管理写操作的局部保护，13A登录、统一访问令牌和多用户隔离仍未完成。没有任意命令、PID、模型路径、远端服务器地址或手工修改状态的HTTP入口。

### ASR-3A：管理页面如何使用这些契约

- “计算节点”和“ASR 实例”来自真实登记接口；页面用独立`/management`报告显示运行状态，不把实例登记字段`runtimeState=unknown`或旧`/sessions`观测解释为当前模型已运行。
- “启动 ASR”“停止 ASR”只向选中实例发送上述固定POST，以最新GET中的Agent会话和命令修订组装请求。管理令牌从项目本地`.env`手动复制到密码框，作为`X-Management-Token`发送；不写URL、浏览器持久化存储或前端构建变量，切换工作台/节点/实例及页面退出或刷新时清除。
- POST返回202只说明意图已受理。页面先放弃命令前的状态，再GET核对，不凭回执显示`ready`或`stopped`。命令并发受限，409、网络失败、超时或异常回执后只读核对，不自动重发；用户依据最新报告决定是否再次操作。
- 正常情况下约每2秒读取一次管理报告；收到的观察有效期为10秒。读取失败、浏览器隐藏/离开或观察过期时，页面放弃旧就绪结论，恢复可见后重新读取。`MANAGEMENT_OBSERVATION_EXPIRED`是客户端生成的观察过期错误，不是后台错误码，也不是Agent超时或进程退出证明。
- 页面区分“未启动”“模型加载中”“可以转写”“正在执行”“停止中”“停止未确认”“启动或运行失败”和“状态未确认”；Agent不可用时不将旧`activeTaskId`作实时任务，不将断网或过期解释为已停止。
- 新ASR提交须匹配选中实例的准确模型版本，且有新鲜可用管理状态、模型已加载并允许接单；忙碌仍可排队。停止/加载/未知期间禁止新提交，原任务详情、结果下载和相同内容的幂等重放保留，最终受理规则仍由后台裁决。

本轮真实页面验证与模拟故障分开记录，没有将再次启动、运行中排空或故障替身记为本轮真实进程证据。页面使用步骤见[ASR独立启停说明](ASR独立启停说明.md)。

## 3. 模型目录

`GET /api/models?taskType=asr`返回`data.items`。`taskType`可为`asr`、`vision`、`llm`或`all`，省略时为`asr`。目录来自持久化模型与版本记录，仅返回当前执行器支持、已启用且设为默认的版本。某类没有满足条件的版本就返回空`items`，不自动改选其他版本。LLM未配置时`taskType=llm`返回空目录；已有登记也不能绕过配置与准确规范检查。

ASR准确规范为 `modelId=whisper-small`，仓库 `Systran/faster-whisper-small`，版本 `536b0662742c02347bc0e980a01041f333bce120`，`taskType=asr`、`executionMode=offline`、`adapterKey=faster-whisper`。

`parameterSchema` 给出 `defaultLanguage`、`autoDetectionValue`、支持的 `languages`；`inputConstraints` 给出模型声明与部署配置取更严格值后的 `maxFileBytes` 和 `maxAudioSeconds`。默认上限为 20 MiB（20,971,520 字节）和 300 秒，可以调低。`outputCapabilities` 为 `text`、`segments`、`language`；`resourceRequirements` 为 `device=cpu`、`computeType=int8`、`maxConcurrency=1`，它描述模型执行配置，不是实时资源报告。

视觉准确规范为 `modelId=yolo-general`、`modelVersion=yolov5n-v7.0-onnx`、`modelRepo=ultralytics/yolov5`、`taskType=vision`、`executionMode=offline`、`adapterKey=yolov5-onnx`。`parameterSchema` 包含 `defaultConfidenceThreshold=0.25`、`defaultIouThreshold=0.45`、`defaultMaxDetections=100` 和 `maxDetections=300`。`inputConstraints` 为有效 `maxFileBytes`、`maxPixels` 及 `formats=["JPEG","PNG"]`，默认10MiB/20,000,000像素。`outputCapabilities=["detections","imageDimensions"]`，资源要求记录CPU、FP16输入、单槽和固定权重SHA。这是规范及配置，不是内存/GPU的实时探测。

视觉规范须经维护命令登记、启用并设为默认，0006迁移只扩结构，不自动登记模型。读取目录不会下载或加载模型。模型是否已加载看 `/api/runtime` 的对应组件；本地文件完整性使用[使用指南](使用与故障处理.md)中的检查命令。全部登记版本及启用、禁用、默认版本操作使用[模型管理维护命令](模型管理说明.md)，没有对应写入 HTTP 接口。

## 4. 上传与幂等

`POST /api/tasks/asr` 必须使用 `multipart/form-data`，由客户端生成正确的 multipart 边界，不要手写 JSON 上传，也不要自行固定 `Content-Type` 而漏掉边界。

| 位置 | 名称 | 要求 |
|---|---|---|
| 请求头 | `Idempotency-Key` | 必填，1—128 字符；首字符为字母或数字，后续允许字母、数字、`.`、`_`、`:`、`-` |
| 文件字段 | `file` | 必须且只能有一个文件；音频实际可解码，且符合大小/时长限制 |
| 文本字段 | `modelId` | 可省略，默认 `whisper-small`；ASR入口须使用ASR模型 |
| 文本字段 | `modelVersion` | 可省略，使用该模型明确设置的默认版本；填写时为 1—64 字符，并须是当前支持且启用的准确版本 |
| 文本字段 | `language` | 可省略，默认 `zh`；`auto` 表示自动识别，其他值须来自模型目录 |

`POST /api/tasks/vision` 同样使用 `multipart/form-data` 和必填 `Idempotency-Key`，文件字段仍是唯一的 `file`。视觉表单如下，不接受 `language`：

| 名称 | 要求 |
|---|---|
| `file` | 一张实际可解码的静态 JPEG/PNG；默认10MiB且不超过20,000,000像素 |
| `modelId` | 默认 `yolo-general`；须属于视觉任务类型 |
| `modelVersion` | 可省略使用明确默认；当前可执行版本为 `yolov5n-v7.0-onnx` |
| `confidenceThreshold` | 默认0.25，须大于0且不超过1，拒绝NaN/Infinity |
| `iouThreshold` | 默认0.45，须大于0且不超过1 |
| `maxDetections` | 默认100，整数1—300 |

图片按实际字节内容识别格式，不靠扩展名判断。EXIF方向归正后记录宽高，透明背景合成到白底，输入哈希仍对应上传原始字节。

两类入口首次受理返回201，`data` 为 `{task, replayed: false}`，响应头 `Location` 指向任务详情。同一调用者、同一幂等键和相同任务类型/文件内容/模型版本/参数返回200、`replayed=true`，并返回原任务的当前状态。显示文件名不参与内容指纹；同一字节内容改名不会因此成为新任务。幂等键在两个入口间共用，同键换任务类型也会冲突。

相同幂等键用于不同内容时返回 409 `IDEMPOTENCY_CONFLICT`。网络中断或超时后，无法仅凭客户端报错判断受理失败：应保持原文件、参数和幂等键重新提交。确实要创建新任务时生成新键；失败或取消的原任务不会因为幂等重放重新运行。

对于已有幂等键，后台先按原任务固定的模型版本核对请求，省略 `modelVersion` 的旧请求也能正确重放。禁用或更改默认版本不会阻止原请求返回原任务；显式改成另一版本、另一模型、另一参数或文件仍会冲突。对新的幂等键，版本在受理时固定，并在数据库提交事务内再次检查可用性。禁用只阻止新受理，不影响已受理任务执行、重试、查询和下载。

PowerShell 示例，使用 Windows 的 `curl.exe`，不是可能指向其他命令的 `curl` 别名：

```powershell
$sample = 'D:\1 研究生\aixm\inference-platform\runtime\samples\asr_example_zh.wav'
$submitKey = [guid]::NewGuid().ToString('N')
$receipt = curl.exe -sS -X POST 'http://127.0.0.1:5000/api/tasks/asr' -H "Idempotency-Key: $submitKey" -F "file=@$sample" -F 'modelId=whisper-small' -F 'language=zh' | ConvertFrom-Json
$receipt | ConvertTo-Json -Depth 8
$taskId = $receipt.data.task.taskId
```

先查看回执是否包含 `data`。`curl.exe` 成功接收 HTTP 错误响应时也可能退出码为 0，所以不能只凭命令没有报错判断受理成功。重试同一次上传时保留 `$submitKey`，不要重新执行生成编号的那一行。

图片示例使用第九部分已有公开样例；成功取得任务编号不代表检测已经结束：

```powershell
$imageSample = 'D:\1 研究生\aixm\inference-platform\runtime\samples\yolo-bus.jpg'
$imageSubmitKey = [guid]::NewGuid().ToString('N')
$imageReceipt = curl.exe -sS -X POST 'http://127.0.0.1:5000/api/tasks/vision' -H "Idempotency-Key: $imageSubmitKey" -F "file=@$imageSample" -F 'modelId=yolo-general' -F 'modelVersion=yolov5n-v7.0-onnx' -F 'confidenceThreshold=0.25' -F 'iouThreshold=0.45' -F 'maxDetections=100' | ConvertFrom-Json
$imageReceipt | ConvertTo-Json -Depth 8
$imageTaskId = $imageReceipt.data.task.taskId
```

## 5. 任务查询、状态与期限

`GET /api/tasks?taskType=vision&page=1&pageSize=20` 返回 `data.items`、`total`、`page`、`pageSize`。`taskType=asr|vision|all`，省略时只查ASR，故旧页面不会把图片当音频展示。`page` 默认1，范围1—1,000,000；`pageSize` 默认20，范围1—100。列表按创建时间从新到旧排列；没有状态、文件名等额外筛选参数。`GET /api/tasks/{taskId}` 直接返回实际类型的 `TaskView`，不接受类型过滤。

`TaskView` 的主要字段：

| 字段 | 含义 |
|---|---|
| `taskId`、`callerId`、`taskType` | 任务编号、固定 `local-user`、`asr`或`vision` |
| `modelId`、`modelVersion`、`executionPlanVersion` | 此任务固定的模型与执行计划版本 |
| `parameters` | ASR为`language`（自动检测`null`）；Vision为`confidenceThreshold/iouThreshold/maxDetections` |
| `input` | 公共`fileName/sizeBytes/sha256`；ASR另有`durationSeconds`，Vision另有`mediaType="image"/width/height`，不伪造音频时长或提供内部磁盘路径 |
| `status`、`message` | 实际状态及说明 |
| `attempt`、`maxAttempts` | 已开始的执行次数和最大次数，包含首次执行 |
| `createdAt`、`updatedAt`、`startedAt`、`finishedAt` | 受理、更新、执行开始和终态时间 |
| `queueDeadlineAt`、`totalDeadlineAt` | 首次受理时固定的等待/总截止时间 |
| `attemptDeadlineAt`、`nextRetryAt` | 当前或最近执行的截止时间、下次重试可投递时间 |
| `error` | `null` 或 `{code, message}`；等待重试时可保留上次执行错误 |
| `resultAvailable` | 是否已有成功结果 |

| 状态 | 页面意义 | 终态？ |
|---|---|---|
| `created` | 已保存，待投递 | 否 |
| `queued` | 通知已入队，等待 Worker | 否 |
| `running` | 已取得执行权，尚未提交结果 | 否 |
| `retry_wait` | 暂态失败，等待有限重试 | 否 |
| `cancel_requested` | 取消已受理，等待停止确认或执行权失效 | 否 |
| `succeeded` | 结果已保存 | 是 |
| `failed` | 最终失败，不再自动重试 | 是 |
| `cancelled` | 任务已取消，不再接受结果 | 是 |

ASR、Vision及在线LLM活动请求共用全局默认20个在途上限，并非每类各20。ASR与Vision各1个执行槽位，分别消费`asr.whisper-small`和`vision.yolo-general`能力队列；不互抢任务。LLM另外受静态实例在线许可约束，不使用这两类Worker或通知。

默认排队600秒、单次执行900秒、任务总期限1800秒、最多执行2次、重试等待5秒。排队期限从首次受理起算，检查 `created/queued/retry_wait`；正在执行时不因排队期限过去而直接失败，但总期限和单次期限仍生效。重新投递或重启不会刷新原排队/总期限。真正取得新的执行权才增加 `attempt`，等待资源不增加次数。

只有明确列出的暂态失败允许有限重试：`WORKER_CHILD_EXITED`、`WORKER_COMMUNICATION_FAILED`、`WORKER_STOPPED`、`LEASE_EXPIRED`、`ATTEMPT_TIMEOUT`、`STORAGE_TEMPORARILY_UNAVAILABLE`。次数或剩余期限不足则最终失败；未知错误、损坏输入、模型错误不自动反复执行。错误历史在数据库保存，目前没有公开的执行历史列表接口。

```powershell
Invoke-RestMethod "http://127.0.0.1:5000/api/tasks/$taskId" | ConvertTo-Json -Depth 8
Invoke-RestMethod 'http://127.0.0.1:5000/api/tasks?page=1&pageSize=20' | ConvertTo-Json -Depth 8
```

## 6. 转写、检测结果与图片访问

`GET /api/tasks/{taskId}/result` 的 `data` 为 `taskId`、`modelId`、`modelVersion`、`schemaVersion`（当前字符串 `"1"`）和 `output`。

ASR的`output`将通用结果与引擎信息分开：

| 字段 | 含义与兼容规则 |
|---|---|
| `text`、`segments`、`audioDurationSeconds` | 全文、分段和输入音频时长。每段含`start/end/text`，时间单位为秒；不为没有分段时间戳的外部引擎伪造内容 |
| `language`、`languageRequested`、`languageProbability` | 实际语言、请求语言和引擎语言置信度；允许缺失或为`null`，不以虚构数值补齐其他引擎未报告的信息 |
| `engineMetadata` | 可选的引擎运行事实对象；存在时用`adapterKey`标识受控实现，其他实际未知的信息可不提供 |
| 顶层历史Whisper执行字段 | `modelRepo/modelRevision/device/computeType/cpuThreads/modelLoadSeconds/transcriptionSeconds/totalSeconds/fasterWhisperVersion/ctranslate2Version`仍可读取，但不要求每个ASR引擎都有这些值 |

`engineMetadata`可包含`adapterKey`、`modelRepo`、`modelRevision`、`device`、`computeType`、`cpuThreads`、`modelLoadSeconds`、`transcriptionSeconds`、`totalSeconds`及`runtimeVersions`。后者是运行库名称到版本的映射，例如当前Whisper会报告`faster-whisper`与`ctranslate2`；不放服务地址、凭据或任意扩展正文。

当前Whisper新结果同时提供`engineMetadata`和原有顶层字段，对应事实必须一致。旧JSON缺少`engineMetadata`时仍可读取，序列化不会强行增加该字段；本阶段不迁移或覆盖历史结果。页面按实际可用信息展示，不能因为整理了通用契约就声称其他ASR服务已验证。

模型版本中已有的`adapter_key`只选择代码维护的允许目录。当前仅支持完整ModelSpec与固定`faster-whisper`实现相匹配的规范；只登记未知`adapter_key`或复制一个模型名称，不会使其可执行。API不接受任意模块、代码、命令或服务器音频路径。

Vision的 `output` 沿用第九部分 `DetectionResult`：`modelId/modelVersion/modelSha256`、`imageWidth/imageHeight`、`coordinateSystem="original-pixels-exif-normalized"`、`detections`、`device/runtimeVersion/inputType/preprocessingVersion`及`loadSeconds/inferenceSeconds/totalSeconds`。每个检测含`classId/className/confidence/box`，框为原图像素`xMin/yMin/xMax/yMax`。空`detections=[]`是成功，不是输入错误。

Worker 常驻模型已加载时，单次结果的 `modelLoadSeconds` 可为 0。配置要求 CPU/int8，实际 `computeType` 以返回值为准，本机已观察到 `int8_float32`。这些耗时是该次执行的测量，不是平台吞吐或完成进度。

```powershell
Invoke-RestMethod "http://127.0.0.1:5000/api/tasks/$taskId/result" | ConvertTo-Json -Depth 10
```

未完成返回409 `RESULT_NOT_READY`；最终失败返回409 `TASK_FAILED`；已取消返回409 `TASK_CANCELLED`。先查询任务详情可取得错误原因。ASR页面的TXT/JSON下载仍由前端基于此接口生成；音频原文件没有公开下载接口。

`GET /api/tasks/{taskId}/image?variant=original` 返回视觉任务输入经EXIF方向归正、透明白底转换后的PNG；它不是原始上传字节。`variant=annotated` 要求任务成功，只使用数据库已提交的检测JSON在受管原图上即时绘制，不再次调用YOLO，不持久化大型PNG产物。省略`variant`等同`original`；其他取值拒绝。

图片接口按任务所有者读取，校验受管输入大小、SHA和尺寸；不接受任意文件路径。`original`在任务受理后即可读取，`annotated`沿用结果未就绪/失败/取消的拒绝规则。读取ASR任务图片返回422 `TASK_TYPE_MISMATCH`。成功类型为`image/png`，`Content-Disposition`为inline文件名，带`nosniff`和`no-store`；错误仍为统一JSON。此接口不等于M06短期签名下载凭证或受租约大型产物存储。

```powershell
Invoke-RestMethod "http://127.0.0.1:5000/api/tasks/$imageTaskId/result" | ConvertTo-Json -Depth 10
Invoke-WebRequest "http://127.0.0.1:5000/api/tasks/$imageTaskId/image?variant=annotated" -OutFile '.\runtime\results\image-task-annotated.png'
```

执行前确认任务已成功、输出父目录存在；示例的本地下载文件名由你指定，已有同名文件可能被下载命令覆盖，与第九部分不覆盖输出目录的本地命令是不同入口。

## 7. 取消

`POST /api/tasks/{taskId}/cancel` 无需请求体，也接受空 JSON 对象 `{}`；不接受其他字段。取消可重复请求，无须 `Idempotency-Key`。

```powershell
Invoke-RestMethod -Method Post "http://127.0.0.1:5000/api/tasks/$taskId/cancel" | ConvertTo-Json -Depth 8
```

返回 `data.task` 和 `data.decision`：

- `cancelled`：未执行任务已直接取消，执行次数不增加。
- `cancel_requested`：执行中的任务已受理取消；继续查询实际状态。回执查询时 Worker 可能已完成收尾，因此 `task.status` 也可能已经是 `cancelled`。
- `already_finished`：任务此前已成功、失败或取消，保持原终态。

取消与成功提交由同一数据库事务规则裁决：成功先提交则保持成功；取消先受理则拒绝迟到结果。HTTP 200 表示此次操作已处理，不表示任意任务都变成已取消。响应超时后可重新查询和重复取消。

运行取消要求 Worker 停止受管模型进程并确认结束。M08 也可在执行权到期后结束逻辑取消，因此 `cancelled` 本身不能证明旧进程已退出；Worker 是否能够接新任务应另看运行状态。停止浏览器、前端或 API 不会自动取消已受理任务。

## 8. 常见错误码

下表为主要 HTTP 错误，不把任务详情中的执行失败码误当成 HTTP 状态。

| HTTP | `error.code` | 含义与处理 |
|---|---|---|
| 400 | `AUDIO_EMPTY` / `AUDIO_DECODE_FAILED` | 空文件、无有效音轨或无法解码；更换音频 |
| 400 | `IMAGE_EMPTY` | 图片上传为空 |
| 404 | `TASK_NOT_FOUND` | 任务不存在或不属于当前固定调用者 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一提交编号对应不同内容；核对后为新任务使用新编号 |
| 409 | `RESULT_NOT_READY` / `TASK_FAILED` / `TASK_CANCELLED` | 查询任务实际状态，不应继续当作成功结果下载 |
| 409 | `INPUT_INTEGRITY_FAILED` | 受管图片大小、哈希或尺寸与任务不一致；保留数据检查原因 |

## 页面链接与结果显示（第十一部分）

- `/?task=<ASR任务编号>`沿用旧链接；`/?type=vision`打开图片工作台，`/?type=vision&task=<图片任务编号>`恢复对应详情。URL的`type`选择前端工作台，API列表/目录的筛选参数仍叫`taskType`，不要混用。
- 当前工作台分别请求ASR或Vision模型和任务列表。API省略`taskType`继续默认ASR；单任务路径返回真实类型，页面检查类型与编号，不能把跨类型数据直接渲染为另一种结果。
- 图片页面提交准确`modelVersion`和三个检测参数；同页不确定提交保留原文件、版本、参数与幂等键，修改内容才发起新提交。刷新只恢复已得到编号的任务，不能恢复尚未确认的浏览器文件与编号。
- 页面“原图”/“检测框图”对应`variant=original|annotated`。JSON下载为完整result数据，检测表格仅做数值显示格式化；PNG下载来自已有图片端点，页面不调用模型或重复处理坐标。
- 图片读取、任务查询和提交失败分别提示；网络错误不是后台任务失败，空`detections`也不是错误。运行取消始终由后台确定，页面不直接改终态。

操作步骤见[使用与故障处理](使用与故障处理.md)第3节，真实浏览器及模拟边界见[第十一部分记录](阶段记录/第11部分-图片检测操作页面-验收记录.md)。

## 9. 独立在线文本通道（第十二部分）

本节是已落盘接口契约；执行证据以[第十二部分记录](阶段记录/第12部分-LLM在线流式通道-验收记录.md)为准。当前没有真实endpoint或LLM模型，不提供自动模拟回答。在线记录保存元数据，不保存输入/回答正文；因此查询与刷新不能重放回答或恢复生成。

### 9.1 服务状态与模型

`GET /api/llm/status`返回`data.configured`、`availability`（`unconfigured|configured`）、`message`、`maxConcurrentRequests`、`activeRequests`、`uncertainPermits`及固定`serviceVerified=false`。`configured`只说明四项部署配置齐备，不会探测上游健康、自动登记模型或证明真实生成成功。默认未配置仍允许读取状态和历史记录。

`GET /api/models?taskType=llm`只展示与当前静态配置准确匹配、已启用且设为默认的在线规范：`taskType=llm`、`executionMode=online`、`adapterKey=openai-chat-completions`。平台标识/版本来自部署配置，`modelRepo`记录上游模型名；地址和密钥不在目录公开。参数为`defaultTemperature=0.7/defaultMaxTokens=512/maxTokens=2048`；限制为`maxMessages=32/maxInputCharacters=16000`，输出能力`text/stream`，资源描述为静态endpoint及`chat-completions-sse`协议，不代表GPU探测。配置和显式登记顺序见[模型管理说明](模型管理说明.md)。

### 9.2 创建与增量事件

`POST /api/llm/requests`使用`application/json`，请求体最多128KiB。JSON如下；其中模型标识与版本须替换为已配置且登记启用的准确值，下面不是可直接运行的真实模型：

```json
{
  "onlineRequestId": "0123456789abcdef0123456789abcdef",
  "modelId": "configured-model",
  "modelVersion": "fixed-version",
  "messages": [{"role": "user", "content": "请介绍这段文字的主要内容。"}],
  "parameters": {"temperature": 0.7, "maxTokens": 512}
}
```

- `onlineRequestId`由客户端在发送前生成，为32位小写十六进制，保存后用于核对不确定回执；`modelId/modelVersion`必填，不能省略版本自动改选。
- `messages`为1—32条，只支持`system/user/assistant`纯文本消息，每条非空，总内容最多16,000个Unicode字符，至少含一条`user`。页面当前发送单条用户消息；API可接受上述有限消息数组。
- `parameters`可省略。温度为有限数字0—2，默认0.7；`maxTokens`为整数1—2048，默认512；拒绝布尔值、数字字符串、未知字段。token数不是汉字数。只支持单答案纯文本，不支持工具调用、多模态或自动续接。
- 使用客户端请求编号去重：同一编号再次创建一律409 `LLM_REQUEST_EXISTS`，包括相同内容。它不会返回第二条生成流，也不使用ASR/图片的`Idempotency-Key`重放规则。连接不确定时用GET查询原编号，不能自动重发POST或静默切换模型。

流成功打开后为HTTP200、`Content-Type: text/event-stream; charset=utf-8`，无缓存；每帧为`event: 类型`和`data: JSON`，空行分隔。公共字段为`type`、从1递增的`sequence`、本次HTTP `requestId`及`onlineRequestId`：

| 类型 | 额外内容 | 含义 |
|---|---|---|
| `accepted` | `record` | 已保存独立在线记录，不表示已经得到模型内容 |
| `heartbeat` | 无 | 连接仍受监督，不代表模型进度或完成比例 |
| `delta` | `text` | 本次增量文字，按顺序追加；UTF-8字符/帧可能跨网络读取块 |
| `done` | `record`，可有`error` | 连接有明确终态；须检查`record.state`，取消也可用done结束，不一律等于completed |
| `error` | `error={code,message}`，通常有`record` | 本次失败；收尾存储异常时可能没有可确认的record，应按编号查询 |

进入流之后不能再依赖HTTP状态码表示后续失败，必须处理结束/错误事件及无终结帧的断流。部分内容后失败应保留“部分输出”说明。上游必须符合当前文本Chat Completions SSE子集，含一致模型/请求标识、明确finish_reason及`[DONE]`；不接收工具调用、隐藏推理内容、音频等扩展。适配器不自动重试、不跟随重定向，不使用系统HTTP代理配置。

### 9.3 状态、限额与查询

`GET /api/llm/requests?page=1&pageSize=20`返回`items/total/page/pageSize`，按受理时间和编号倒序。页码1—1,000,000，每页1—100。单条查询为`GET /api/llm/requests/{onlineRequestId}`，未找到404，格式错误422；不接受`taskType`，不会混入`GET /api/tasks`。

`OnlineRequestView`公开：`onlineRequestId/callerId/modelId/modelVersion/instanceId`、`state/permitState`、`acceptedAt/deadlineAt/firstTokenAt/endedAt`、`outputCharacters/finishReason/error`、`cancelRequested/cancellationConfirmed`。时间为UTC；实例ID是内部静态实例标识，不公开地址。没有owner、指纹、租约、完整输入或回答。`firstTokenAt`记录收到首个非空内容的时间，`outputCharacters`是后台接收的字符计数，不是token数，也不是浏览器一定已收到的字符数。

状态为`accepted`（已受理）、`waiting_instance`（等待许可）、`streaming`（已获许可，可能尚未有首字）、`completed`、`failed`、`cancelled`。前三者计入全局在途。许可另分`waiting/held/released/uncertain`，已经逻辑结束但上游停止不明时仍占用对应实例额度，不因刷新或重启就假设释放。

默认在线并发许可1、准入等待2秒、连接超时5秒、读取间隔超时30秒、总期限120秒、慢消费者容忍5秒、处理权租期15秒。输出最多131,072字符。总期限不随心跳刷新；网络读取超时不能代替总期限。具体范围和调整说明见[配置指南](使用与故障处理.md)。这些是保护配置，不是容量测试结论。

### 9.4 取消与保守收尾

`POST /api/llm/requests/{onlineRequestId}/cancel`仅接受空请求体或`{}`，成功返回`data.request`及`decision=cancel_requested|already_finished`，可重复调用。受理停止后查询实际终态，不能把回执200当作引擎已经停止。

浏览器离开、隐藏或切换工作台时会中止当前读取并尝试请求停止；服务连接关闭也进入统一收尾。正常结束、取消、断流、超时、慢消费和处理进程失联均记录安全错误/终态，生成不自动重放。当前通用HTTP适配器无法确认远端GPU已停止；未确认时保留`permitState=uncertain`，新请求可能等待后被拒绝。只有维护者在真实引擎侧确认停止后，才可使用维护命令释放，不能通过网页修改许可；见[维护步骤](模型管理说明.md)。

### 9.5 主要在线错误

| 错误码 | 含义 |
|---|---|
| `LLM_NOT_CONFIGURED` | 流开始前503，尚未配置，不创建成功生成 |
| `LLM_REQUEST_EXISTS` / `LLM_REQUEST_NOT_FOUND` | 已有编号冲突409 / 不存在404 |
| `VALIDATION_ERROR` / `LLM_INVALID_REQUEST` | 输入字段、消息、参数或请求形态不符合约定 |
| `INFLIGHT_LIMIT_EXCEEDED` | 全局在途已满，流开始前429 |
| `LLM_CAPACITY_UNAVAILABLE` | 有限等待后仍无实例许可，可含未确认占位 |
| `LLM_UPSTREAM_UNAVAILABLE` / `LLM_UPSTREAM_REJECTED` | 无法连接上游 / 上游拒绝，不公开其原始错误正文 |
| `LLM_UPSTREAM_PROTOCOL_ERROR` / `LLM_STREAM_INTERRUPTED` | 协议不支持、数据损坏或缺少正常结束，部分内容不当作完整回答 |
| `LLM_TIMEOUT` / `LLM_SLOW_CONSUMER` / `LLM_STREAM_LIMIT_EXCEEDED` | 超时、读取过慢或接收上限保护 |
| `LLM_CANCELLED` / `LLM_OWNER_LOST` | 已请求取消 / 原处理进程失联；均不自动重放 |
| `LLM_STORAGE_UNAVAILABLE` | 无法确认记录状态；核对迁移和原编号，不能假定资源释放 |

`/?type=llm&request=在线编号`只恢复元数据。正文只在当前页面内存，复制/TXT下载只导出当时已收到内容，未正常完成的文件标注`partial`。刷新不会恢复正文或重新生成。

## ASR-4A：外部文件调用契约（v2.8）

本节是外部 ASR 的现行补充；上述本机 Whisper/YOLO 的重试、取消和管理规则不直接套用于远端请求。首轮固定 `remote-v2-sensevoice`，后台调用对方同步文件接口，浏览器仍使用原 `POST /api/tasks/asr`、任务查询、结果与下载。

### 状态接口

`GET /api/asr/external/status` 无查询参数，返回标准 `{data, requestId}`。没有远端启停、任意 URL 代理或 HTTP 人工解除占位接口。

| `data` 字段 | 含义 |
|---|---|
| `configured` | 地址、模型标识及固定版本是否完整配置；不等于可调用 |
| `available` | 当前是否允许提交外部任务；Worker 报告、占位和健康共同参与裁决 |
| `state` | `unconfigured` 未配置、`unavailable` 不可用、`ready` 可调用、`running` 正在调用、`uncertain` 远端结果未知、`stopping` 本机调用进程停止接单中 |
| `observedAt` | 本次状态观察时间，可空；页面 10 秒未获新确认时保守失效 |
| `message` | 安全的状态解释，不包含地址、凭据、证书路径或上游原始错误正文 |
| `currentTaskId` / `uncertainTaskId` | 当前外部任务或待核对的任务编号；无值为 `null` |
| `modelId` / `modelVersion` | 配置的模型身份；未配置时为 `null` |

即使移除配置，既有未确认调用仍可显示为 `uncertain`。外部 Worker 运行或健康接口可达不证明远端旧请求已结束，也不证明模型权重版本已实测。

`GET /api/runtime` 增加可空 `remoteAsrWorker`（组件标识 `remote_asr_worker`）、`externalCallConcurrency`（未配置 0、配置后 1）和 `externalAutomaticRetry=false`。原 `executionConcurrency=2`、`automaticExecutionRetry=true` 保留本机 ASR/Vision 的含义，不应用于外部调用；本机调用进程的报告不能充当远端节点资源报告。

### 模型、提交与结果

`GET /api/models` 中 `modelRepo` 可为 `null`；新增 `executionLocation=local/external` 与 `managementMode=managed/external_call_only`。外部模型保持 `taskType=asr`、`executionMode=offline`、`adapterKey=remote-v2-sensevoice`，参数中的 `languageMode=server`；未配置/未登记启用的模型不会出现在可提交目录。

外部上传继续使用 multipart `file`、`modelId`、`modelVersion` 和 `Idempotency-Key`。`language` 应省略，兼容 `auto` 表达由服务端决定；不支持指定 `zh/en` 等客户端语言。原 Whisper 默认中文行为保持。有效上限仍为 20 MiB/300 秒，受理前验证音频，不能从对方更高限额推定平台扩容。

新 TaskView 字段为 `cancelAllowed`（后台当前是否允许取消）、`cancelUnavailableReason`（不可取消原因或 `null`）及 `remoteOutcome`。后者本机任务为 `null`，外部任务可能为 `not_dispatched`（尚未派发）、`pending`（调用中）、`confirmed`（已确认结果/结束）或 `unknown`（远端结果未知）。它们补充现有任务状态，不是另一套任务状态机。

外部转写结果继续使用原 `text/segments/audioDurationSeconds/engineMetadata`。时间戳经校验，全文由返回分段拼接，时长使用已接受音频的本地解码值。外部未返回的语言、语言概率、设备、计算精度和耗时为缺省；`data.confidence` 不映射为语言置信度。API 版本只记为 `runtimeVersions` 的 API 元信息，不冒充模型版本。旧 Whisper 结果 JSON 与查询保持兼容。

### 取消、错误和不确定性

外部任务仅在尚未领取时可取消；领取后 `POST /api/tasks/{taskId}/cancel` 返回 `409 REMOTE_ASR_CANCEL_UNSUPPORTED`，即使 HTTP 连接断开也不能将远端推理判为已取消。外部任务 `maxAttempts=1`，不自动重试；原上传幂等重放仍只是确认已有平台任务，不自动重发推理。

| 错误码 | 处理原则 |
|---|---|
| `REMOTE_ASR_NOT_CONFIGURED` / `REMOTE_ASR_UNAVAILABLE` | 未配置、Worker 未就绪/停止接单或服务不可用；不制造成功结果 |
| `REMOTE_ASR_RESULT_UNKNOWN` / `REMOTE_ASR_UNKNOWN` | 请求可能已经发出但无法确认结果；任务失败并保留外部通道占位，暂停新受理/领取 |
| `REMOTE_ASR_NOT_SENT` / `REMOTE_ASR_REJECTED` | 能够确认没有发送或明确被拒绝；仍不自动重试 |
| `REMOTE_ASR_CANCEL_UNSUPPORTED` | 409，任务已被领取，外部接口不支持取消 |
| `REMOTE_ASR_CONFIRMATION_REQUIRED` / `REMOTE_ASR_RELEASE_CONFLICT` | 维护 CLI 未明确确认请求结束，或本机对应调用尚未收尾/记录状态不符 |

结果未知时，`remote_cli release` 需经人工核对、明确确认和说明，解除后原失败任务不改写、不重发。整平台退出只确认本机所属进程，远端结束未知继续保留；具体命令见[外部ASR接入说明](外部ASR接入说明.md)。实际 HTTP 状态以 AppError 定义为准，上游原始 `detail` 不直接透传到页面。


## v2.12本机-2A：ASR目标目录与资源观测

`GET /api/asr/external/targets?offset=0&limit=20`返回标准`{data, requestId}`，仅查询本地数据库。它不访问校园服务、不调用健康/资源/推理接口，不登记目标或刷新观测时间，不修改任务、许可和未知占位。没有HTTP登记、启用或资源写入接口；写入由受控维护CLI完成。

查询参数仅有`offset`与`limit`：offset默认0、范围0—1000000；limit默认20、范围1—100。只接受十进制整数字符，重复字段、未知字段、负数、小数或超限返回422 `VALIDATION_ERROR`。目标按targetId升序分页，不使用其他列表的page/pageSize。

| `data`字段 | 含义 |
|---|---|
| `observedAt` | 本次只读查询的数据库时间，不是新的服务器采样 |
| `total/offset/limit/items` | 总目标数、偏移、每页上限与当前页目标列表 |
| `routingEnabled` | 本部分固定false，新增调度尚未接回执行；不取消原调用池能力 |

| `items[]`字段 | 含义 |
|---|---|
| `targetId/capacityGroupId` | 平台目标编号及共享容量组，不是物理GPU编号 |
| `targetLimit/groupLimit` | 原平台许可限额，不是实测设备吞吐或资源余量 |
| `mode/legacyEnabled` | legacy为原执行目标，catalog_only为待接入目录；legacyEnabled保存原目标enabled事实 |
| `connectionRevisionId/catalogRevisionId` | 连接快照修订和目录元数据修订；旧目标无目录时后者为null |
| `deviceKind/verificationState` | unknown/gpu/cpu是目录声明；verificationState固定unverified，不能据此宣称绑定成功 |
| `modelId/modelVersion` | 连接修订中的平台模型身份；未知上游版本按原本地接入修订表达 |
| `hasDeviceEvidence/hasCompatibilityEvidence` | 仅表示保存了说明，不表示资料已核实 |
| `observations` | 每个scope的最新采样，最多target与capacity_group各一条；无报告为[] |
| `routingEnabled` | 固定false，新增目录不参与Worker领取 |

`observations[]`包含`observationId/scope/source/evidenceKind/observedAt/recordedAt/expiresAt/freshness`、`reportedHealth/reportedAvailableConcurrency`及可空的`gpuUtilizationPercent/gpuMemoryFreeMiB/cpuAvailableCores`；`usableForScheduling`固定false。`provided`只是提供资料，`isolated`只是隔离测试资料，两者都不等于实测通过。

最新报告按采样时间选择，时间相同才比较写入顺序；迟到的旧样本不会覆盖新采样。freshness以数据库当前时间和采样时间加TTL计算：有效期内fresh，到期stale，时钟早于采样或录入时间时unknown。GET不会延长有效期，也不会在最新报告过期后回退到旧报告。资源值null表示未知、0表示报告值为0；两者都不自动修改平台许可或授予执行权。

成功响应不包含连接地址、证书路径、TLS例外、原始连接/元数据快照、设备标识或原始证据文本。旧`remote-default`继续按原配置及原任务指纹执行，未知结果保持占位；只读目录不把旧任务转发到新目标。真实设备/容量接入和Worker调度分别留后续本机-3A及本机-2B按获准条件完成。


## v2.12本机-2B：任务路由安全投影

已有上传、任务、结果和取消路径保持；没有新增HTTP路由登记或目标启用接口。受控`register-route`只登记资料，详情见[操作说明](ASR调度执行说明.md)。

有`asr_task_routes`记录的任务在TaskView（提交回执、详情、列表和取消回执所包含的任务）增加可选`routing`对象；旧任务、未使用新路由的任务直接省略该字段，迁移不反填。任务列表批量取得路由投影，不按每行分别查询。

| `routing`字段 | 含义 |
|---|---|
| `routingRevisionId` | 任务受理时固定的路由修订，重启后不随默认配置更换 |
| `selectionState` | waiting尚未冻结目标；selected在领取事务已冻结，不表示已转写成功 |
| `catalogRevisionId/targetId/deviceKind` | 选中目录、平台目标及gpu/cpu；waiting时为null，不猜测设备 |
| `reasonCode` | 已冻结选择的策略原因；未选择时可为null，不用一个空值声称GPU已满 |
| `evidenceKind` | 已选中的isolated/provided资料类别；当前执行仅isolated，waiting可为null |
| `selectedAt` | 带UTC时区的冻结时间；尚未选择为null |

该投影不返回地址、证书/TLS设置、原始策略/设备证据、CPU性能样本或完整内部选择快照。它只解释原任务的选择，不替代status、attempt、remoteOutcome、租约及结果状态，也不建立重发通道。逻辑任务模型与候选服务的实际连接修订独立核对，旧模型版本/任务指纹不覆盖。

新路由只能在明确隔离环境运行，原真实remote-default仍按unknown/1使用；目录GET中的routingEnabled=false和unverified仍表示“登记不会授予真实调度权限”。本轮隔离执行证明平台规则衔接，不是校园SenseVoice、真实GPU/CPU或吞吐验证。页面展示留本机-2C。


## v2.12本机-2C：只读调度诊断与任务解释

### 调度区域的状态

`GET /api/asr/external/scheduling`无查询参数，成功返回标准`{data, requestId}`。未知或重复查询字段返回422，不支持的写方法返回405。诊断只读取本地配置、路由及调用池记录，不访问上游健康/资源/转写，不登记目标、不刷新观测、不冻结选择、不签发许可或解除占位。

| `data`字段 | 含义 |
|---|---|
| `observedAt` | 本次数据库时钟下的诊断时间，不是服务器采样 |
| `mode` | legacy原固定通道；isolated本地隔离检查通过；blocked配置/调用池条件未满足 |
| `routingConfigured` | 是否设置新路由修订，不等于目标已核实或可以实际转写 |
| `executionScope` | legacy沿原通道；isolated只允许隔离运行；disabled新路由当前被阻止 |
| `reasonCode/message` | 安全原因码与中文说明；不透出原始配置、连接地址或证据 |
| `candidateCount` | 0—8个已读取的固定候选；未配置或无法读取时可为0，不代表真实物理资源总量 |

该响应没有available字段。HTTP200说明诊断成功返回，mode=isolated也不证明真实GPU/CPU就绪；legacy不代表旧通道可用性已经检查。需要原通道状态时仍按既有status/capacity契约理解，不把不同接口的状态互换。

### 任务routing解释增量

旧无路由任务继续省略routing。新路由任务保留2B全部字段，增加以下可空/可空列表的诊断字段：

| 字段 | 含义 |
|---|---|
| `observedAt` | 详情实时只读解释时间；列表冻结投影为null，不冒充新资源评估 |
| `message` | 当前安全中文解释，不改变原任务状态 |
| `reasonCategory` | selected已选；waiting等待；blocked记录/条件阻止；outcome_unknown结果未确认；terminal终态 |
| `statusCode` | 当前诊断原因，与已冻结选择的reasonCode分开 |
| `candidates` | 最多8项；每项targetId/deviceKind/eligible/reasonCode/message，仅安全候选说明，无原始证据或地址 |

任务详情重新读取原路由、调用绑定、池/槽和最新观测进行只读解释；列表批量读取路由记录及轻量状态，不对每个等待任务执行资源评估，候选为空。已选任务的reasonCode仍是原选择原因，即使后来成功、失败或结果未知也不覆盖；等待任务reasonCode可以反映本次等待解释，实际候选仍未冻结。

即使某次详情评估给出GPU_PREFERRED或eligible=true，selectionState仍可为waiting，说明只是当前候选建议；Worker还须在原领取事务重新准入，不由GET开始任务。查询不延长期限、续租或增加执行次数。

远端结果未知优先显示outcome_unknown；即使管理员按原流程释放了容量，也不会把任务原未知结果改写为已确认，不自动重发或切换CPU。结果状态与实际占位分别核对，不能从一条诊断文案推断许可已经释放或一定仍被占用。

本轮不改数据库结构、Worker或任务状态机。新增调度区域和详情解释仅展示这些安全字段；资源未知/过期、读取失败或数据无效时显示未确认。真实服务及GPU/CPU能力仍待3A/3B，测试和浏览器证据单独记录。
