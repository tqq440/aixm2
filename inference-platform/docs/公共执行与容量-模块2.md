# 公共执行与容量（模块 2）

本模块给 ASR、YOLO、LLM 建立共用的执行内核：给调用编号、检查额度、选择目标、签发执行租约、接收结果和记录事件。仍复用原 `tasks`、`online_requests` 和任务结果，不再造一份业务状态。

**当前交付内部执行基础层，日常请求尚未切换。** 真实 HTTP/SSE 适配和后台监控在模块 4，对外 API Key 与页面时间线在模块 5。Redis 在模块 3；本轮没有更换队列，也没有验证真实模型。

## 一次调用的过程

1. 受理方创建原任务，并在同一 SQLite 写事务中调用 `bind_in_transaction`，固定服务修订。新任务队列使用 `common.` 加服务/模型身份摘要；旧队列任务禁止重新绑定。
2. 离线执行器调用 `claim_round`，按服务和模型轮询，每轮每队列最多成功领取一个。先检查最早任务，阻塞时继续找符合条件的任务，轮询位置持久化。
3. 在线受理方调用 `accept_online`，只保存生命周期和请求指纹，不保存聊天正文。随后 `wait_online` 默认短等最多 2 秒，不刷新原请求期限。
4. 一个 `BEGIN IMMEDIATE` 事务同时检查应用、目标、全部共享资源组和平台额度。全部满足后，写入预约、租约和分配事件。
5. `dispatch` 在事务外调用适配器回调，先将调用标为“进入可能发送阶段”，同一租约只能进入一次。长调用由适配器通过 `renew` 保活，续租不能延长总截止时间。
6. 校验结果、原请求终态、容量释放及对应事件在一个事务中提交。成功返回后，后续 Redis 执行器才可以确认通知。

本轮通过隔离回调验证第 5 步，尚未接日常 HTTP 适配器。首批校验复用原 ASR、现有本地 YOLO 结果契约，以及仅含字符数/结束原因的 LLM 完成元数据。通用远端 YOLO 结果归一化、SSE 结束信号验证留模块 4。适配器不能绕过租约发送，也不能把普通断线当成功。

## 额度与设备

- 一次调用对应用、目标和每个共享组各占一个额度；`held` 和 `uncertain` 都计额。某项不足时不预约其他项。
- 目标按规范化的根地址和调用路径识别，同接口换服务名、模型名或目标别名不能增加额度；当前声明不一致时取较小目标额度。
- 三类服务共用 GPU 时须配置同一共享组；目标可以同时引用 GPU、主机等多个组。
- 默认额度 1，提高额度要填写容量依据。这是获准的平台并发预算，不代表显存、利用率或其他调用方的占用已被测量。
- 固定模式可使用明确登记的未知设备目标；自动模式需要设备、兼容、容量依据和新鲜健康检查。GPU 按有效目标额度的占用比例选择。
- GPU 状态不明、检查失败或过期时等待，不据此自动回退 CPU。健康检查目前仍需显式触发，五分钟后过期；自动采集在模块 4。
- ASR CPU 自动承接复用原性能评估，必须有对应服务修订/目标的不可变性能样本，满足规模、并发和剩余时间预算。YOLO、LLM 不自动回退 CPU，可配置固定 CPU 目标。
- LLM 与离线任务共用容量，但本版不承诺两者严格公平，也不抢占正在执行的调用。

应用编号目前是内部可信身份。登记额度不等于签发 API Key，校园网鉴权在模块 5。

## 取消、故障与未知结果

| 情况 | 行为 |
|---|---|
| 未进入发送阶段就取消或租约过期 | 确认未发送，结束并释放预约 |
| 进入发送阶段后断线、超时或执行器失联 | 结果未知，保留占位，不重发、不换目标 |
| 发出取消请求但未确认远端停止 | 记录取消请求，继续占位 |
| 重复领取/发送/完成 | 不重复调用，相同完成结果幂等处理，最多释放一次 |
| 旧租约或冲突结果到达 | 拒绝覆盖当前记录 |
| 后来显式核实可信远端终态 | 内部 `resolve_unknown` 追加核对/释放事件，不改写原超时或失败历史 |
| 仅查询失败、404、429、格式错误 | 不能作为可信终态；监控协议在模块 4 |

`resolve_unknown` 只结算已结束的未知占位，不冒充“取回结果并成功”。远端成功而结果未保存时，原任务保留原失败/未知事实；迟到结果获取和归一化在模块 4 补齐。核对证据只保存摘要，防止误粘贴秘密或正文。

旧占位尚未全部映射到公共组，因此保守互斥：有旧运行/未知调用时公共层等待；有公共占位时旧执行器不领取新任务。旧任务、旧指纹、许可和结果不搬账、不重绑定。关闭公共开关也不能绕过已存在的公共绑定和占位；相关请求须恢复开关后处理，不会交给旧恢复器重试。

## 任务日志

`inference_task_events` 追加记录受理、等待原因变化、状态变化、分配、预约明细、发送、完成、取消、未知和释放。公共事件关联应用、原请求、调用编号、执行次数、目标和服务修订。原请求初始事件早于绑定，通过原请求编号关联，不伪造此前调用信息。

状态和对应事件在同一事务保存；事件写失败一并回滚结果、状态和预约。重复等待原因、单纯续租和每个 token 不重复写事件。事件不含正文、音频、图片、完整头部、密钥、连接地址或原始上游响应。

平台已分配设备与实际设备分别表达：分配事件中的 `actualDevice=null`，不会宣称模型已加载到 GPU。逐任务进度、实际设备和查询异常快照在模块 4，没有接口时仍显示缺口。

启用公共模式后，JSON 运行日志使用 `api-<PID>.log`、`worker-<PID>.log` 等独立滚动文件，沿用每文件 2 MiB、3 个备份；未启用时保留原命名。标准文件处理器吸收写入错误，不撤销已提交结果。任务事件首版不自动清理。

## 本机管理 API

前缀 `/api/admin/common-execution`，采用服务目录相同的本机连接、Host、来源限制；写入须 JSON。这些不是对外推理接口。GET 只读本地资料，不调度、不恢复过期、不查询服务。

| 方法 | 路径 | 用途 |
|---|---|---|
| PUT | `/applications/{applicationId}` | 内部额度和服务权限，含 `applicationId/concurrencyLimit/allowedServices/enabled/expectedVersion` |
| POST | `/cpu-profiles` | 登记不可变 ASR CPU 性能依据 |
| GET | `/capacity` | 当前额度、已占/未知数量、旧占用是否尚未映射 |
| GET | `/invocations/{invocationId}` | 调用状态、冻结修订、目标和原因，不返回租约令牌 |
| GET | `/applications/{applicationId}/tasks/{taskId}/events` | 离线时间线 |
| GET | `/applications/{applicationId}/online/{onlineRequestId}/events` | 在线时间线 |

事件使用 `afterSequence` 游标，默认 50、最多 200 条，返回 `nextSequence/hasMore`。归属不一致返回 404；旧任务明确提示“详细事件从启用本模块后开始记录”。

本轮只升级隔离库。日后启用须正常停止相关组件、核对在途/未知调用、成套备份数据库/文件/服务配置，完成迁移和核对后正常重启。开启开关只启用内部内核及事件记录，不自动启动真实适配器。公共表已有记录则拒绝降级删除，使用前向修复或备份恢复。
