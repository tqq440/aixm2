# 业务协议与监控（模块 4C2）

> 后续增量：模块5已交付公共应用Key、入口Node、归属接口和管理页面；详见[模块5](公共API与管理-模块5.md)。本文“下一模块5”等保留4C2时点含义，默认不开启日常通道。

本部分把 4C1 的“调用身份和结果恢复”接上真正的 HTTP 协议代码：中心执行器读取已受理的媒体，经目标 Node 调用业务；Node 在后台查询业务状态，先保存结果，中心再保存权威结果并释放额度。这里的“真正 HTTP”包含回环 HTTP 协议验证，不代表实验室模型已完成联调。

CPU/GPU 的内存分配、显存回收、模型缓存和业务内部队列由业务侧负责。平台仍管理应用、调用目标与所有共享组的并发许可，区分平台排队与业务排队，不把容器运行或 GPU 占用当作模型就绪。

## 当前交付和默认边界

| 项目 | 当前行为 |
|---|---|
| ASR | Remote-V2、OpenAI Audio，校验上传指纹、实际音频时长，转换为 PCM16 WAV；最多 20 MiB / 300 秒 |
| YOLO | 明确的 `vision-json-v1` HTTP 检测协议，JPEG/PNG ≤10 MiB / 2000 万像素；支持逻辑模型和自定义类别 |
| LLM | Chat Completions 文本 SSE，经 Node 转发；须结束原因加 `[DONE]`，普通 EOF 不算成功 |
| 查询 | 可选 `job-json-v1`，关联本次调用、执行次数和两端修订；缺接口如实显示 |
| 执行器 | 显式启动、固定进程锁、租约续期、Node 就绪探测、结果采集；不自动启动业务容器 |
| 默认配置 | `NODE_BUSINESS_ENABLED=false`，中心公共执行仍默认关闭；日常库和旧入口未切换 |
| 下一模块 | 模块 5：入口 Node 的公共 `/api/v1`、API Key、应用隔离与管理页面 |

内部执行凭据不是对外应用 Key。本轮没有开放无需网页登录的完整公共中转入口，不能拿管理 API 代替应用鉴权。

## 运行链路

1. 中心仅对已登记 Node、相容模型/协议/调用模式、有效配置和新鲜就绪状态的目标领取任务。轮询队列、共享组额度等继续复用原公共层；Node 观测不替代设备和容量证据。
2. 中心读取受理时保存的媒体，校验大小、SHA256 与元数据。在原预约上固定 Node 启动实例、目标和配置修订，不再预约一次。
3. Node 在发送前再次检查身份、媒体、解码限制、证书、凭据和接单门禁；发送记录与事件先落盘，网络调用在数据库写事务之外。
4. 同步响应验证后，Node 持久化结果；异步响应只表示业务已受理，仍保留中心额度。Node 不建立推理等待队列。
5. 后台采集远端状态/结果，中心从 Node 保存的档案取回。中心结果保存、完成事件与容量释放在一个事务中提交；Redis 消息仍在结果结算后确认。
6. 明确未发送的输入/门禁拒绝有持久 `_NOT_SENT` 回执，可以结束并释放预约。已经发送但不明的调用不会重发、换目标或靠期限释放。

Node 重启把未决执行保留为未知，通过原调用编号查询；同步无查询接口的未知请求须人工核对。中心重启继续采集已有档案，不重新 POST 推理。配置新修订只影响新请求。

## 登记业务协议

沿用 [4A 管理接口和启动实例绑定](独立Node基础-模块4A.md)。在 Node 的服务 `config` 中增加 `upstream`；保存、绑定实例、有效生命周期报告仍分别完成。以下是服务配置片段，并非整个注册请求：

```json
{
  "internalBaseUrl": "http://127.0.0.1:8013",
  "upstream": {
    "protocol": "remote-v2",
    "invokePath": "/infer",
    "mode": "async",
    "upstreamModel": null,
    "tokenEnv": "NODE_UPSTREAM_TOKEN_ASR",
    "timeoutSeconds": 300,
    "connectTimeoutSeconds": 5,
    "query": {
      "protocol": "job-json-v1",
      "statusPath": "/jobs/{requestId}/status",
      "resultPath": "/jobs/{requestId}/result",
      "cancelPath": "/jobs/{requestId}/cancel",
      "idSource": "invocation",
      "intervalSeconds": 5,
      "timeoutSeconds": 3
    }
  }
}
```

所有路径必须是根相对路径，不含跳转、查询串、路径穿越；查询模板只能含一个 `{requestId}`。`idSource=job` 则用受理响应里的 `jobId`。使用系统 TLS 信任或 Node 本地 `caFile`，不关闭证书校验、不自动跟随跳转、不读取代理环境，不重试推理 POST。

同步服务使用 `mode=sync`，没有查询能力时写 `query: {"protocol":"none"}`。正常最终响应仍可完成，进度与实际设备为空。异步服务必须声明状态接口以及 `resultPath` 或 `resultInStatus=true`，只有任务编号而没有完成闭环会登记 `COMPLETION_UNAVAILABLE` 并拒绝接单。

中心目录的 `protocol`、`invocationMode`、`modelId` 与目标 `node.configRevision` 必须对应 Node；异步目标的 `monitoring` 同样声明结果获取方式。Node 绑定沿用 [4C1](Node执行恢复-模块4C1.md)，两个内容修订不要求相互相等。Node 接口缺口、未核实运行条件与中心目录问题清单分别保留。

| 协议 | 实际 HTTP 请求 | 最终响应 |
|---|---|---|
| `remote-v2` | multipart：`audio` WAV、`outputs=transcript`、`engine=sensevoice`、`request_id` | 复用既有 `success/engine/details.segments`，若给出 request_id 必须匹配；不宣称支持指定识别语言 |
| `openai-audio` | multipart：`file` WAV、`model`、`response_format=json`、可选 `language`、`request_id` | 复用既有 `text` 和可选分段；不把普通 202 当同步完成 |
| `vision-json-v1` | multipart：`image` 原始图片、`model`、`parameters` JSON、`request_id` | 下方检测协议；坐标以 EXIF 归一后的原图为准 |
| `chat-completions-sse` | JSON：配置的上游 `model`、文本 `messages`、生成参数、`stream=true,n=1` | 标准文本 chunk、明确 finish_reason、最后 `[DONE]`；非文本 delta 拒绝 |

媒体上传到 Node 使用生成文件名；Node 不接受任意路径或下载 URL。临时解码文件在独立 Node 目录中清理，不把原媒体写进运行日志。LLM 只短暂持有输入/转发 token，不把聊天正文或 token 作为恢复日志落盘。

异步提交，以及声明查询的文件提交，额外携带 `context` JSON：中心的 `ExecutionCommand`（调用编号、执行次数、修订等，不含密钥或媒体）。声明查询的 LLM 在请求头提供 `X-Request-ID`、`X-Inference-Attempt`、`X-Inference-Service-Revision`、`X-Inference-Config-Revision`；无查询时不添加关联头。

YOLO 同步结果示例：

```json
{
  "schemaVersion": "vision-json-v1",
  "modelId": "campus-detector",
  "modelVersion": null,
  "imageWidth": 640,
  "imageHeight": 480,
  "coordinateSystem": "original-pixels-exif-normalized",
  "detections": [{
    "classId": 100,
    "className": "custom-object",
    "confidence": 0.9,
    "box": {"xMin": 10, "yMin": 20, "xMax": 100, "yMax": 200}
  }]
}
```

`modelId` 要与平台逻辑模型一致；如果服务提供版本则必须匹配，未提供保持 null。图片尺寸、框边界、阈值和数量都验证。不伪造模型文件指纹或实际设备。原本地 YOLO 的固定模型/类别/文件指纹约束仍保持，远程结果用独立 schema。

## 参考逐任务状态协议 job-json-v1

异步受理响应必须返回完整关联身份，HTTP 202 示例：

```json
{
  "invocationId": "0123456789abcdef0123456789abcdef",
  "attempt": 1,
  "serviceRevision": "中心传来的64位修订原值",
  "configRevision": "Node传来的64位修订原值",
  "jobId": "job-001"
}
```

上例修订是说明文字，测试或真实实现必须回显请求中的 64 位十六进制原值。状态和结果 GET 都返回同一结构，加以下字段：

```json
{
  "state": "running",
  "progress": 35,
  "stage": "infer",
  "queuePosition": null,
  "actualDevice": {"kind": "gpu", "deviceId": "0", "namespace": "service"},
  "result": null
}
```

此片段须与上方五个身份字段合并；不是独立完整响应。状态只能为 `queued/running/succeeded/failed/cancelled`。进度是 0—100 的可空数值，缺少不按时间估算；阶段为 ≤64 位英文标识。身份、执行次数或修订不匹配时整次查询无效，不覆盖上一次可信快照。

`succeeded` 不等于平台成功：必须取得并验证 `result`。结果可在状态响应内（须声明 `resultInStatus=true`），或从单独结果路径取回，后者返回相同身份、`state=succeeded` 和 `result`。ASR result 使用平台 `TranscriptionResult`，含 `text/segments/languageRequested/audioDurationSeconds`；视觉 result 使用上方 schema；LLM 查询确认完成须给 `OnlineCompletion`（完成原因和字符数），不回传聊天正文。所有字段以 [Node OpenAPI](node-foundation.openapi.json) 为准。

`actualDevice.namespace` 默认为 `service`：容器里的 `GPU 0` 不自动代表宿主机 `GPU 0`。只有业务能提供宿主机设备证据时才报 `host`。平台分配设备单独放在中心 `assignedDevice`，主机资源采样不填充逐任务实际设备。

取消 POST 携带 invocationId、attempt、serviceRevision、configRevision；响应为相同五个身份字段加 `accepted=true`。这只是接受取消请求，只有后续可信 `cancelled` 或其他终态才释放额度。缺取消接口、查询失败或页面关闭不代表远端停止。

## 采集、异常与日志

Node 一个后台采集器负责本机登记服务的逐任务查询：默认 5 秒，每个业务地址与状态路径最多同时 1 次，整个 Node 采集进程最多 4 次。别名指向同一地址/路径时共用限制；不要给同一物理服务配置不同域名绕开限制。中心结果采集器另外限制最多 4 次并发，仅取 Node 已保存档案。**这些是进程内限制；多 Node 间全平台查询总数的统一预算须在模块 6 多机验收时配置核实，当前不宣称跨进程全局限额已实现。**

单次查询默认 3 秒、最大 10 秒。普通失败按 5/10/20/40/60 秒退避，采用配置间隔起步，并遵守有界 Retry-After（数字或 HTTP 日期）。查询不重叠，网络不占数据库写锁。浏览器 GET 永远只读快照；重复开页面不会触发业务查询。

| 情况 | 保存与呈现 |
|---|---|
| 没有查询接口 | 接入缺口；进度/实际设备为空；有效同步响应或正常 SSE 仍可完成 |
| 查询超时、404、429、错误格式 | 保存监控错误码和时间，保留上次可信状态，不改推理终态 |
| 服务 succeeded、结果未取得 | 服务完成、结果待取，平台未成功，额度仍占用 |
| 到达调用期限 | 自动采集停止、事实未知，不重推理、不自动释放；后续显式核对 |
| 迟到结果 | 保存迟到档案和核对事件，保留原超时历史，幂等处理容量 |
| 已终态又收到旧查询 | poll token 与终态检查拒绝覆盖 |
| 流断线/消费者提前关闭 | 未完成且停止未确认，保留未知占位；不重放 token |

平台事件记录接收/等待/分配/发送、监控变化、结果保存/完成/容量释放。Node 事件注明调用编号、次数、目标修订和来源；进度变化合并限频，终态立即记录。取消即使未得到服务 ACK 也保留请求与未确认事件。事件、状态及结果按对应 SQLite 事务保存；运行日志失败不撤销结果。日志不含凭据、请求头、音频图片、聊天正文或原始错误响应。

## 内部接口与显式执行器

Node 内部接口均使用独立中心执行 Bearer 凭据：

| 接口 | 行为 |
|---|---|
| POST `/node/internal/v1/executions/file` | multipart：`command` JSON、`manifest` JSON、`file`；总请求 ≤20 MiB +64 KiB |
| POST `/node/internal/v1/executions/stream` | JSON：`command` 与在线 `request`；响应 SSE `delta/receipt`，请求 ≤192 KiB |
| GET `/node/internal/v1/executions/{id}/monitoring` | 保存的监控回执，不含结果正文，不访问业务 |
| POST `/node/internal/v1/executions/{id}/reconcile` | `{}`，显式查询原调用，包括过期调用；不重新推理 |
| POST `/node/internal/v1/executions/{id}/cancel` | `{}`，请求取消，ACK 不结束任务 |

原元数据 execute、执行详情、结果 GET 继续兼容。媒体 manifest 由中心根据已受理资料生成，指纹随调用固定；不让外部用户填写内部身份绕过中心。Node 执行档案只存恢复必需的元数据和验证后结果，不存在线请求正文。

中心新增本机管理 GET `/api/admin/common-execution/invocations/{id}/monitoring` 与 POST `/reconcile`、`/cancel-remote`（空 JSON），受现有本机管理限制，非公共应用接口。只读、显式核对的区别可这样测试：

```bash
# ID 必须替换为平台已有的公共调用编号；不是旧 taskId。
curl "http://127.0.0.1:5000/api/admin/common-execution/invocations/$ID/monitoring"
curl -X POST -H 'Content-Type: application/json' -d '{}' \
  "http://127.0.0.1:5000/api/admin/common-execution/invocations/$ID/reconcile"
```

配置通过受保护环境文件/进程环境提供。Node 使用 `NODE_BUSINESS_ENABLED=true`、独立 `NODE_EXECUTOR_TOKEN`，可选业务凭据 `NODE_UPSTREAM_TOKEN_ASR` 等，服务中只登记变量名。业务密钥不得复用管理、观察、中心执行或报告凭据。

中心独立 env 须显式开启 `INFERENCE_COMMON_EXECUTION_ENABLED=true`，指定已迁移至 0019 的 SQLite、上传目录、日志目录、目录里 executorTokenEnv 指向的凭据。按模块 3 选择 Redis 时配置 `INFERENCE_COMMON_QUEUE_BACKEND=redis` 及受保护 Redis 地址；缺客户端/连接不降级到 SQLite 派发，恢复与结果保存继续保守处理。隔离开发才使用 SQLite 通知。

```bash
python -m backend.modules.worker.node_executor --env-file /absolute/path/central.env --workers 4
# 检查一个周期并等待本周期派发完成，然后退出：
python -m backend.modules.worker.node_executor --env-file /absolute/path/isolated.env --once
```

执行器要求数据库文件已存在、迁移正确、公共开关开启；不会创建/升级日常库。原主进程不会自动启动这个 worker。Node 的启动与 init-db 继续用 4A CLI；Docker 仍默认关闭。LLM 由桥接层 `stream_online` 执行，公共接收入口在模块 5，不放进离线 worker。

## 迁移与验收边界

中心 `0019` 给派发档案增加监控 JSON；Node 独立 `0004` 给执行档案增加监控 JSON 和取消终态。没有监控的新旧字段不改写原修订、任务号、结果指纹或旧报告。非空调用/执行历史阻止丢证据的降级。旧任务不补造事件链。

本轮只迁移隔离资料，日常仍 0014、42 任务/42 上传；启用日常环境仍须按原计划暂停接收、核对在途、备份和正常重启，不能让旧 Worker 与新链路执行同一任务。
