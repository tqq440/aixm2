# 模型管理说明

第八部分增加持久化模型目录，第十部分扩展固定视觉模型，第十二部分增加配置明确的在线文本规范。本说明依据代码编写；实际测试与真实模型边界见[开发进度](开发进度.md)及[第十二部分记录](阶段记录/第12部分-LLM在线流式通道-验收记录.md)，不能仅凭登记或配置判断模型已经验收。

模型目录保存“模型叫什么、哪个版本、允许什么输入、由哪类适配器执行”。它不保存模型权重，也不会下载模型、加载模型或启动Worker。当前支持准确匹配的Whisper small、固定YOLOv5n ONNX，以及四项在线配置生成的准确LLM规范；后者仍需真实服务，本机尚未提供。任意登记其他模型或修改核心定义不会自动得到执行能力。登记、启用、设置默认与模型是否已就绪分别核对。

## 1. 查看已登记版本

在开发目录打开 PowerShell，沿用现有环境：

```powershell
Set-Location -LiteralPath 'D:\1 研究生\aixm\inference-platform'
$projectPython = 'C:\Users\86199\miniconda3\envs\project311\python.exe'
& $projectPython -m backend.modules.models.model_registry list --page 1 --page-size 20
```

命令需要已经迁移的数据库，不会自行建表。成功退出码为 0；参数或业务规则拒绝为 2，其他未处理失败为 1。通过 `$LASTEXITCODE` 查看命令退出码。业务错误写入标准错误流，带 `error.code` 和请求编号；日志位于配置日志目录的 `model-registry.log`。

返回 `items`、`total`、`page`、`pageSize`；每项包含：

| 字段 | 含义 |
|---|---|
| `spec` | 不可覆盖的模型版本定义 |
| `enabled` | 是否允许新任务受理 |
| `isDefault` | 省略版本号时，是否明确选择这个版本 |
| `executionSupported` | 当前执行器是否支持这份准确的定义；不是模型已加载的证明 |

分页默认每页20项，最多100项。维护命令列出全部已登记版本，包括禁用的版本；`GET /api/models`只列出当前执行器支持、已启用且被选作默认的版本，并默认过滤为ASR。图片目录用`taskType=vision`、在线目录用`taskType=llm`、全部类型用`taskType=all`。页面按工作台查询对应目录；维护命令有记录，而其他类型工作台没有显示该模型，是类型筛选的正常结果。

## 2. 启用、禁用与默认版本

以下命令中的固定版本来自已验证的本地模型：

```powershell
$modelVersion = '536b0662742c02347bc0e980a01041f333bce120'
& $projectPython -m backend.modules.models.model_registry disable --model-id whisper-small --model-version $modelVersion
```

禁用后，新的 ASR 请求会被拒绝，模型不再出现在可提交目录。已经受理的任务继续使用原版本执行或重试；旧任务、结果和下载仍然存在。禁用不终止 Worker，不删除权重、音频或结果。页面刷新或重新获取模型目录后反映变更；已打开页面提交旧选项时仍由后台再次检查。

需要恢复受理时：

```powershell
& $projectPython -m backend.modules.models.model_registry enable --model-id whisper-small --model-version $modelVersion
& $projectPython -m backend.modules.models.model_registry set-default --model-id whisper-small --model-version $modelVersion
```

默认版本只接受已启用、执行器支持的版本。禁用默认版本时保留默认指针，不自动选择其他版本；重新启用时恢复原默认关系。每个模型标识有自己的默认版本，不按版本名称自动推断“最新”。这些变更保存到数据库，重启后保留。

第十部分初次接入视觉模型时，先完成0006迁移并校验已有本地权重，再用项目保存的[准确YOLO规范](examples/yolo-model.json)：

```powershell
& $projectPython -m backend.modules.vision.prepare_model --check
& $projectPython -m backend.modules.models.model_registry register --file '.\docs\examples\yolo-model.json'
& $projectPython -m backend.modules.models.model_registry enable --model-id yolo-general --model-version yolov5n-v7.0-onnx
& $projectPython -m backend.modules.models.model_registry set-default --model-id yolo-general --model-version yolov5n-v7.0-onnx
```

0006迁移只改变结构，不运行这些管理操作。每条成功后再运行下一条；准确规范来自`REGISTRY_SPEC`，包括权重SHA、FP16输入、阈值与图片限制。不要改同一版本的核心内容来绕过限制。需要禁用图片新受理时，用相同标识/版本执行`disable`；已有图片任务、结果和已受理任务执行不因禁用消失。已有正确目录无需每次启动重新登记。

## 3. 登记版本

`register --file` 接受 UTF-8 JSON 文件，最大 1 MiB，字段采用 camelCase。核心字段如下：

| 字段 | 要求 |
|---|---|
| `modelId`、`modelVersion` | 必填，每项 1—64 字符；标识以字母或数字开头，后续可用字母、数字、点、下划线、短横线，版本额外允许 `+` |
| `taskType` | `asr`、`vision` 或 `llm` |
| `executionMode` | ASR、Vision 必须为 `offline`；LLM 必须为 `online`。执行器支持检查独立于登记 |
| `modelRepo` | 可省略或为 `null`；填写时长度 1—256 |
| `parameterSchema` | 参数定义 JSON 对象 |
| `inputConstraints` | 输入限制 JSON 对象 |
| `outputCapabilities` | 非空且不重复的字符串列表，最多 64 项；每项 1—64 字符，格式与 `modelId` 相同 |
| `adapterKey` | 适配器标识，1—64 字符，标识格式与 `modelId` 相同 |
| `resourceRequirements` | 资源要求 JSON 对象 |

例如，将维护命令中现有 Whisper 规范导出，再重复登记，可以检查相同内容的幂等行为。此操作使用已有真实规范，不引入一个未经验证的新模型：

```powershell
$catalog = & $projectPython -m backend.modules.models.model_registry list --page 1 --page-size 100 | ConvertFrom-Json
$currentSpec = $catalog.items | Where-Object { $_.spec.modelId -eq 'whisper-small' -and $_.spec.modelVersion -eq $modelVersion } | Select-Object -ExpandProperty spec
$currentSpec | ConvertTo-Json -Depth 12 | Set-Content -LiteralPath '.\runtime\tmp\whisper-small-spec.json' -Encoding UTF8
& $projectPython -m backend.modules.models.model_registry register --file '.\runtime\tmp\whisper-small-spec.json'
```

执行导出前确认查询成功且选中了现有版本，临时目录需存在。首次登记返回 `created=true`，默认禁用且不会自动设为默认；相同标识、版本和内容重复登记返回 `created=false`，保留原可用状态和默认关系。同一版本不同定义返回 `MODEL_VERSION_IMMUTABLE`，应为真正不同的规范使用新版本号，不能覆盖已有版本来改变旧任务含义。

Whisper定义要求CPU、int8、单槽；YOLO定义要求CPU、FP16输入、单槽和固定权重SHA。LLM规范由明确部署配置生成，详见第6节；任意改动同一版本核心定义都不会得到执行权限。网页不提供登记、启用或禁用按钮，也没有模型管理写入HTTP接口。

## 4. 与任务和配置的关系

新上传可携带 `modelVersion`，页面会提交当时选择的准确版本。省略时后台取该模型明确设置的默认版本，并把结果固定到任务中。已受理的任务不会因以后更换默认版本而改用另一个模型。

使用原幂等键重发原文件和参数时，后台先认出原任务并按原版本核对，因此禁用或默认版本变化不妨碍正确的重放；显式版本、模型、参数或文件与原请求不同仍返回冲突。新的任务在数据库写事务内再次核对可用状态，避免上传期间禁用后仍被新受理。

模型定义中的输入限制与`.env`部署上限取更严格的值。ASR仍为最多20MiB、300秒；视觉为静态JPEG/PNG、10MiB/20,000,000像素，配置允许调低，不能借登记绕过上限。两个工作台分别展示对应目录返回的有效限制。扩展ASR模型、GPU、大文件或长音频等待课题组安排及后续阶段验证。

## 5. 常见错误

| 错误码 | 处理方法 |
|---|---|
| `MODEL_NOT_FOUND` / `MODEL_VERSION_NOT_FOUND` | 用 `list` 核对模型标识和版本 |
| `MODEL_DEFAULT_UNSET` | 对已有且可执行的启用版本使用 `set-default` |
| `MODEL_DISABLED` | 判断是否需要允许新任务，再使用 `enable`；旧任务无需重新启用即可查询 |
| `MODEL_EXECUTION_UNSUPPORTED` | 当前 Worker 不支持该准确规范；登记不等于实现模型适配器 |
| `MODEL_VERSION_IMMUTABLE` | 不覆盖旧版本；不同规范使用新版本号 |
| `MODEL_SPEC_FILE_INVALID` / `MODEL_SPEC_FILE_TOO_LARGE` / `VALIDATION_ERROR` | 核对文件路径、UTF-8 编码、1 MiB 限制及字段 |
| `MODEL_REGISTRY_UNAVAILABLE` | 核对数据库配置、迁移和日志；不要删除数据库来绕过错误 |

管理命令可以在服务运行时更新目录，但迁移和配套数据备份仍应先安全停止平台。启动、停止和备份方法见[使用与故障处理](使用与故障处理.md)。

## 6. 以后接入真实LLM服务

**当前没有真实LLM服务，这些步骤是在服务提供后执行的维护说明。**第十二部分不下载权重、不启动vLLM或GPU进程。平台只对接受限的纯文本Chat Completions SSE；vLLM官方说明其提供`/v1/chat/completions`接口，具体模型还需要相应chat template。这说明候选协议存在，不证明任意vLLM部署与本平台已联调。[vLLM官方在线服务文档](https://docs.vllm.ai/en/latest/serving/online_serving/)

先从服务提供者获得以下四项，一起写入本地`.env`或启动进程环境，不能只填其中一部分：

| 配置 | 含义 |
|---|---|
| `INFERENCE_LLM_ENDPOINT` | 完整HTTP(S)地址，路径必须为`/v1/chat/completions`；无查询串、片段或内嵌凭据 |
| `INFERENCE_LLM_MODEL_ID` | 平台中的模型标识，不与已有ASR/YOLO标识混用 |
| `INFERENCE_LLM_MODEL_VERSION` | 本次固定部署版本；改变模型或关键规范时明确新版本 |
| `INFERENCE_LLM_UPSTREAM_MODEL` | 服务实际接受并在流中返回的准确模型名 |

服务需要密钥时另配`INFERENCE_LLM_API_KEY`，只保存在本地配置/环境，不写到前端、规范文件、URL或验收报告。模板在[env.example](../env.example)，四项身份/地址默认注释，保留未配置状态。修改配置后按[启动说明](使用与故障处理.md)重启API；配置只声明目标，不自动探测健康、下载模型或登记版本。

完成0007迁移、核对四项真实值后，先导出配置对应的准确规范。以下命令创建唯一临时文件，命令成功后才登记：

```powershell
$llmSpecJson = & $projectPython -m backend.modules.llm.requests_cli spec
if ($LASTEXITCODE -ne 0) { throw 'LLM 配置规范导出失败，请先处理提示。' }
$llmSpec = $llmSpecJson | ConvertFrom-Json
$llmSpecPath = Join-Path (Get-Location) ('runtime\tmp\llm-spec-' + [guid]::NewGuid().ToString('N') + '.json')
New-Item -ItemType Directory -Path (Split-Path $llmSpecPath) -Force | Out-Null
[System.IO.File]::WriteAllText($llmSpecPath, ($llmSpec | ConvertTo-Json -Depth 12), [System.Text.UTF8Encoding]::new($false))
& $projectPython -m backend.modules.models.model_registry register --file $llmSpecPath
```

确认登记成功，再依次启用和设默认；每条成功后再执行下一条：

```powershell
& $projectPython -m backend.modules.models.model_registry enable --model-id $llmSpec.modelId --model-version $llmSpec.modelVersion
& $projectPython -m backend.modules.models.model_registry set-default --model-id $llmSpec.modelId --model-version $llmSpec.modelVersion
```

`spec`只导出当前配置生成的核心定义，不包含endpoint和key；登记不会验证生成。原有版本的不可变规则继续生效。目录使用`GET /api/models?taskType=llm`，服务配置看`GET /api/llm/status`。准确规范被支持、已启用默认、连接已配置仍不等于真实模型验收完成，`serviceVerified`固定为false。

首次真实服务联调应单独记录正常文本、分块/结束、服务模型名、拒绝/超时、主动停止及服务端计算是否结束。当前协议不处理工具调用、多模态、推理专用字段或自动重连；已经产生部分输出后不能自动换模型拼接。

## 7. 未确认许可的人工核对

在线记录的`permitState=uncertain`表示平台无法确认上游计算结束；该占位继续计入对应实例额度。关闭本地HTTP连接、页面显示已取消或重启API都不是远端停止证据。当前没有引擎专属远程取消/资源回收确认接口。

先在服务端按请求时间、模型和可用的请求关联信息检查，必要时由服务维护者确认对应请求或实例已经停止；仅确认后执行：

```powershell
$onlineRequestId = '替换为实际32位小写十六进制在线编号'
& $projectPython -m backend.modules.llm.requests_cli release $onlineRequestId --confirm-engine-stopped
```

该命令只允许把**已结束且uncertain**的记录改为released，不触发新的生成，也不结束远端进程；标志参数代表维护者已完成外部核对，不能拿它跳过核对或解决任意“繁忙”。未确认/不适用分别返回`LLM_STOP_CONFIRMATION_REQUIRED`、`LLM_RELEASE_NOT_ALLOWED`。维护日志为`llm-maintenance.log`；成功返回更新后的元数据，退出码遵循公共CLI约定。
