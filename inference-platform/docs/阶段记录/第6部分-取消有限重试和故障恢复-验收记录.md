## 2. 具体规则

未执行任务取消后进入 `cancelled`，尝试次数不变。运行任务先进入 `cancel_requested`；此后成功提交不能覆盖取消。Worker 先终止受管子进程并确认进程句柄已结束，再调用取消收尾。若租约先过期，M08 可结束逻辑取消，但本机槽位仍由 Worker 的进程确认和文件锁保护；页面明确提醒另看 Worker 运行状态。

取消接口无请求体（也接受空 JSON 对象），返回 `{task, decision}`；decision 为 `cancelled`、`cancel_requested` 或 `already_finished`。已成功、已失败或已取消的终态不会被改写。不存在或不属于固定调用者 `local-user` 的任务返回 404；错误输入走统一校验响应。取消任务查询结果返回 409 `TASK_CANCELLED`。

允许重试的代码为 `WORKER_CHILD_EXITED`、`WORKER_COMMUNICATION_FAILED`、`WORKER_STOPPED`、`LEASE_EXPIRED`、`ATTEMPT_TIMEOUT`、`STORAGE_TEMPORARILY_UNAVAILABLE`。损坏输入、文件完整性错误、缺失输入、协议或未知模型错误采用不重试策略。错误分类不是所有异常都重试。

重试将旧执行写入历史，同时增加投递版本、保存 `retry_wait` 和待投递事件；保存成功后才确认旧通知。再次真正取得执行权时才增加 `attempt`。失败回执丢失可按历史幂等重放；成功结果已保存但 ACK 丢失时，重复通知读取终态后确认，不重复推理。到达最大次数后保留最终错误和历史，不自动无限重放。

默认并发为 1、最大在途为 20、排队期限 600 秒、单次执行期限 900 秒、任务总期限 1800 秒、最多 2 次执行（包含首次）、租约 30 秒/续期 10 秒、重试等待 5 秒。所有非终态计入在途数量；容量检查与任务创建在同一 SQLite 写事务中，超过上限返回 429，拒绝任务的音频会清理。

排队/总期限从数据库确认首次受理的时间确定，重试不刷新；最大次数同样保存为任务快照。单次期限每次执行重新计算，总期限继续约束所有执行。预算不足以等待下一次重试时直接最终失败。Worker 还固定保存较早期限对应的本地单调时钟预算，即使随后控制/续租查询出错，也不能靠续租延长本次预算；数据库调用本身仍可能带来停止检查延迟，不承诺硬实时终止。

## 5. 停止与运行方法

真实验收中 API 27112、投递器3704、重启 Worker 16652 均按 Ctrl+Break 退出，退出码0。故障注入的原 Worker 29708 明确强退，退出码1；Vite 13712 接收 Ctrl+Break，退出码3221225786（Windows 控制台中断），不记为0。被取消、父进程强退及最终停止涉及的模型子进程均通过预先持有的进程句柄确认结束。5000、5173、4173 端口已关闭。

再次使用时按 [README](../../README.md) 的四个窗口步骤：先执行迁移检查，再分别启动 API、投递器、Worker、前端，打开 `http://127.0.0.1:5173`。每个窗口进入对应目录后执行一条运行命令，不把四个服务命令一次性粘进一个阻塞窗口。

停止时，想保留结果就先等任务完成；想放弃任务先点取消。随后依次在 Worker、投递器、API、前端窗口按 Ctrl+C，并等命令提示符回来。直接停止 Worker 可能触发有限重试，不等于取消任务；关闭页面也不取消后台任务。
