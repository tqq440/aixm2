3. 持久控制流程：幂等 operationId、配置/控制修订检查、单服务单未决操作、门禁关闭、受控启动、排空、SIGTERM、退出确认、预热、恢复、版本切换及有条件回退。
4. 命令 issued 阶段先保存，Docker/业务 HTTP 在写事务外执行；未知结果不自动重发。Node 重启保留已有容器和未知操作，显式 reconcile 后只继续有证据的阶段。
5. 人工 abort 要求全部登记容器确认停止、人工核实未决控制命令结束，只存证据摘要；保持接单关闭，不强停、不修改任务终态或中心容量。
6. 业务 assignment 与 lifecycle-v1 兼容控制字段；关联操作/实例/修订和更大序号证明排空/恢复，HTTP ACK、旧空队列、缺接口或超时都不冒充成功。
7. 一键管理 CLI 只经过 Node API，核对 Node ID，记录/查询原 operationId；不因提交结果不明或等待超时换编号重发。
8. 标准库只读采集 Windows/Linux CPU与内存，固定 nvidia-smi 查询；后台采样、持久快照、过期/失败标记和保留最后可信值，GET 不采样。
