## 完成了什么

### 页面行为

| 区域 | 输入、判断和输出 |
|---|---|
| 新建转写任务 | 选择或拖入单个音频，选择后台支持的模型及语言；客户端检查空文件和大小，后台仍负责真实解码与最终准入；展示上传中、成功、失败和受理结果未知 |
| 任务列表 | 真实分页，每页 20 条；显示音频名、时长、状态、提交时间、失败摘要；选择任务加载详情 |
| 任务详情 | 显示任务编号、音频信息、任务状态；成功后显示全文、分段时间、实际设备、模型版本、尝试次数和耗时 |
| 结果操作 | 复制模型原始全文；下载 UTF-8 TXT 或完整 `TaskResultView` JSON，文件名含音频名和任务编号前缀 |
| 运行状态 | 读取 `/api/runtime`，显示 API 连接、Worker 加载/就绪/繁忙/停止/报告过期/错误、投递器状态；API 断开后显示状态未知 |
| 说明与窄屏 | 中文使用说明弹窗、键盘焦点、结果选项卡键盘操作；桌面双栏，窄屏纵向布局，不强行把全部内容挤在一屏 |

没有假数据、虚构 GPU 指标、估算完成百分比或剩余时间。任务未完成时不能下载成功结果。尚未实现取消、执行重试、故障接管或一键启动全部服务；这些继续遵循第六、第七部分计划。

### 请求与轮询规则

- 页面只通过同源 `/api` 访问真实后台；Vite 开发及预览代理到本机 Flask。没有新增后台 CORS 放行或修改业务规则、数据库、模型。
- 支持 `GET /api/models`、`GET /api/runtime`、`GET /api/tasks`、任务详情和结果查询，以及 multipart `POST /api/tasks/asr`。
- API 错误保留后端消息和请求编号。读取超时为 10 秒，提交超时为 120 秒；超时不是后台任务失败的结论。
- 未完成任务及运行状态，在前一轮请求完成后等待 2 秒再更新，避免慢请求叠加。终态详情和已取得结果不继续重复读取；终态列表可手动刷新以发现其他窗口的新任务。
- 页面变为隐藏、触发 `pagehide` 或组件卸载时，清除定时器并中止在途请求；恢复可见时刷新。旧任务、旧分页请求即使晚到，也不能覆盖当前选择。
- 当前任务编号保存在 URL 的 `task` 参数中，刷新页面重新查询。重复点击当前任务保留已显示结果。
- 上传使用 `Idempotency-Key`，同步防止双击。网络错误、超时、5xx 或页面隐藏导致受理结果未知时，同一页面保持文件和参数重试会沿用原键；主动更换输入或新建任务才换键。整页刷新后不会恢复浏览器文件或未确认提交的键，需先查任务列表。
- 页面中止 HTTP 查询或关闭浏览器不取消后台已受理任务；执行始终由 Worker 负责。

## 如何运行

### 日常启动

先在三个 PowerShell 窗口分别启动原有后台入口，每个窗口先设置工作目录和 Python 路径：

```powershell
Set-Location -LiteralPath 'D:\1 研究生\aixm\inference-platform'
$projectPython = 'C:\Users\86199\miniconda3\envs\project311\python.exe'
```

| 窗口 | 执行命令 |
|---|---|
| 1：API | `& $projectPython -m backend.modules.api.run` |
| 2：投递器 | `& $projectPython -m backend.modules.dispatcher.task_dispatcher` |
| 3：Worker | `& $projectPython -m backend.modules.worker.asr_worker` |

本机数据库迁移和模型准备已经完成；另一套环境需先按 [README](../../README.md) 准备。第四个窗口启动页面：

```powershell
Set-Location -LiteralPath 'D:\1 研究生\aixm\inference-platform\frontend'
npm.cmd run dev
```

打开 <http://127.0.0.1:5173>。首次练习可选择 `D:\1 研究生\aixm\inference-platform\runtime\samples\asr_example_zh.wav`，语言选中文，提交后查看结果。TXT 和 JSON 保存到浏览器选择的下载位置；JSON 来自已保存结果，不会重新运行模型。

API 仍只监听本机 5000；Vite 开发与预览分别为 5173、4173，均只监听 `127.0.0.1`，端口被占用则报错。`frontend/env.example` 中 `INFERENCE_API_TARGET` 默认 `http://127.0.0.1:5000`；需要改端口时复制为 `frontend/.env` 后修改并重启 Vite，不混用后台 `.env`。代理拒绝远程主机、登录凭证和额外路径/查询参数。

### 安装、构建和测试

当前机器已经安装依赖。只有在没有 `node_modules` 的源码目录才需要重新安装：

```powershell
npm.cmd ci --registry=https://registry.npmjs.org --cache='../runtime/npm-cache'
npm.cmd run build
npm.cmd test
```

构建在 `frontend/dist`。后台启动后，可执行 `npm.cmd run preview` 打开 <http://127.0.0.1:4173>，验证构建产物；这是本机预览，不是生产托管。

Playwright 使用已安装 Edge。默认 `npm.cmd run e2e` 只跑模拟断网用例，两项真实测试跳过。四个入口运行后，以下命令会真实新增一条任务并执行模型：

```powershell
$env:PART5_REAL = '1'
npm.cmd run e2e
Remove-Item Env:PART5_REAL
```

### 停止

若希望当前任务正常完成，先等任务进入终态。之后依次在 Worker、投递器、API、前端窗口按 Ctrl+C，等命令提示符恢复；不要结束电脑上全部 Python 或 Node 进程。关闭浏览器或停止 Vite 不会取消已受理任务。Worker 中途停止的行为与第四部分一致，当前没有自动恢复或取消功能。

## 问题与处理

- 系统 npm 缓存目录不可写，安装改用本项目 `runtime/npm-cache`；没有修改全局 npm 配置或升级 Node/npm。
- 重复点击当前任务曾清空结果并短暂加载，已增加同任务保护和测试，最终 18 项通过。
- 首次模拟断网的 `**/api/**` 规则也匹配 Vite 的 `/src/api/client.ts`，导致测试自身阻断页面；已限制为 URL 路径以 `/api/` 开头，单独复跑通过。
- 首轮全页截图保留滚动位置，固定侧栏位置不适合审阅；调整为回到顶部后只读复拍，并适当增大文字。
- 验收辅助管理程序与 Vite 共用标准输入，终端控制命令未及时生效。随后核实本次进程身份，向对应进程组发送 Ctrl+Break 并用句柄确认退出；辅助管理程序最终在 KeyboardInterrupt 后执行清理并退出，不能把所有进程描述为退出码 0。日常使用按独立终端说明操作，该临时管理程序不是交付的一键运行脚本。
- 原规范提及的 `0-生命周期规范.mdc` 仍未找到；本机目录不是 Git 仓库，没有提交或推送源码。
