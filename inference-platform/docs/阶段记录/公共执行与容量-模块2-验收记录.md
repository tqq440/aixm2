## 本轮实现

公共调用引用原 tasks/online_requests，服务修订固定，旧队列任务禁止重绑定。离线按服务/模型轮询，符合条件的最早任务优先，每轮每队列最多成功一个；LLM 默认短等待 2 秒。应用、目标及多个共享组在同一 SQLite 写事务中全部满足才预约，未知占位计额。目标别名不扩容，GPU 使用可信资料，ASR CPU 复用原性能规则，YOLO/LLM 不自动回退 CPU。

内部 dispatch 的适配器回调在事务外执行，单次发送权、租约、结果校验、原请求终态和容量结算已实现。尚未发送可安全结束释放，进入发送阶段后超时/失联保留未知占位；旧执行不能覆盖，不自动重试。显式迟到终态核对幂等释放，但不改写原超时历史，也不冒充已经取得结果。

事务事件记录原请求状态和公共调用的受理、等待原因、分配设备、预约明细、发送、完成、取消、未知、释放。分配设备与实际设备分开，实际设备缺失仍为空。重复原因和续租不刷事件，正文/凭据/原始上游响应不入事件。公共模式 JSON 运行日志按 PID 分文件，沿用滚动策略。

本机管理接口包含内部应用额度、CPU 性能登记，以及容量、调用、应用所属事件的只读 GET。没有暴露领取/发送租约接口，没有提前开放校园网推理 API。进度和真实设备采集、远端 YOLO/SSE 归一化仍在模块 4，API Key/页面时间线在模块 5。
