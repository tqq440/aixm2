## 本部分做了什么

本地同步流程为：`modules/asr` 接收命令参数 → Schema 校验 → `service/asr` 检查输入、检查模型并调用运行库 → `data/asr` 保存完整结果。音频解码、重采样、哈希等纯工具位于 `utils`。

| 文件或模块 | 实际行为 |
|---|---|
| `backend/config/settings/app_settings.py` | 增加固定模型目录/仓库/提交、CPU/int8、线程数、文件和时长限制，统一环境校验 |
| `backend/config/settings/model_environment.py` | 模型下载的 XET 缓存定位到项目运行目录；不改系统环境变量 |
| `backend/service/asr/model_preparation_service.py` | 显式下载准入、固定版本与完整性检查、本地模型复用；转写不调用下载流程 |
| `backend/data/asr/model_store.py` | HF 下载缓存、暂存文件、清单读取/保存、发布已校验目录；修复前保留旧目录 |
| `backend/utils/audio/audio_utils.py` | PyAV 逐帧解码为 16kHz、单声道 float32；按实际样本数有界解码，拒绝损坏包/帧和无音轨文件 |
| `backend/service/asr/asr_service.py` | 音频大小/时长准入、语言支持检查、模型懒加载、生成器完整消费、结果与实测信息转换 |
| `backend/schema/asr/asr_schema.py` | 输入、清单、全文、分段和时间等契约；内部 snake_case，JSON camelCase |
| `backend/service/asr/local_transcription_service.py` | 本地转写与保存流程；输出路径已存在时在加载模型前拒绝 |
| `backend/data/asr/result_store.py` | UTF-8 JSON 保存；独占创建，不覆盖既有文件；写入失败清理本次残片，不报告成功 |
| `backend/modules/asr/prepare_model.py` | 单独模型准备命令；`--check` 只检查本地文件 |
| `backend/modules/asr/transcribe_file.py` | 一次性本地转写命令，结果自动保存后退出 |
| `backend/common/cli/execution.py` | 复用配置/日志，命令失败返回非零状态和带编号的结构化错误 |

与设计的对应关系：这只落实 M12 后续需要复用的音频处理及调用 X03 运行库的基础能力，**没有实现 Worker**。未新增业务表或迁移，未实现上传接口、任务状态、租约、通知队列、投递器或前端。原架构网页与根目录设计文档未修改或发布。

## 审查发现及修复

1. 运行库在本地缺 tokenizer 时可能有远程兜底，因此加载前检查四个必需文件与清单，显式指定本地路径和 `local_files_only=True`；模型缺失明确报错。本次另以离线环境和网络连接拦截验证真实重复运行。
2. small 自带 99 个语言码，当前运行库语言全集还包含 small 没有的 `yue`。本项目固定模型的语言准入排除了它，避免接收后才失败。
3. 时长配置正数极小时会换算为零样本，已把配置下限设为至少一个 16kHz 样本。
4. 写入失败后关闭文件也可能再次失败，已将关闭阶段包含在错误清理范围，补充故障注入测试；不会把未保存的结果报告为成功。
5. CLI 校验错误和用户中断原本缺少失败日志，现统一记录错误码与命令编号。
