## 1. 启动前检查

在 PowerShell 中执行以下两行，后面的后台命令都以这个目录为起点：

```powershell
Set-Location -LiteralPath 'D:\1 研究生\aixm\inference-platform'
$projectPython = 'C:\Users\86199\miniconda3\envs\project311\python.exe'
```

本机已有 `project311` / Python 3.11.16、Node 24.15.0、npm 11.12.1、前端依赖，以及固定版本 Whisper small 和 YOLOv5n ONNX。日常启动不需要重建环境、重新安装依赖或下载模型。第十部分升级前按第6节先备份并迁移，按[模型管理说明](模型管理说明.md)登记视觉规范。直接使用 Python 完整路径可以避开终端 Conda 自动激活脚本问题。

运行环境检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-environment.ps1
```

检查输出逐项结果，整体成功时退出码为 0；有项目未满足时为 2。它不会安装、迁移或下载。这里的 `-ExecutionPolicy Bypass` 仅对本次 PowerShell 进程有效，不修改全局策略。脚本参数或解释器路径本身错误时，也可能返回其他非零码。读完提示再修复对应项，不能把“健康接口能打开”当作全部环境已就绪。

如果脚本受到本机 PowerShell 执行策略限制，直接执行同一 Python 检查入口，不必为此修改系统策略：

```powershell
& $projectPython -m backend.modules.maintenance.check_environment --node-path 'D:/develop/node/node.exe'
```

## 2. 日常一键启动、查看、停止

在开发目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-platform.ps1
```

脚本启动API、投递器、Node Agent、Vision Worker和Vite共5个入口，等待Agent在线及Vision模型就绪。ASR此时默认停止；Agent复用原Worker控制逻辑，显式启动后才创建Whisper模型子进程。打开 **<http://127.0.0.1:5173>**，按第3.1节在“ASR 服务管理”中启动；也可继续使用命令：

```powershell
& $projectPython -m backend.modules.agent.agent_cli start
& $projectPython -m backend.modules.agent.agent_cli status
```

等待管理状态确认ASR模型就绪后再提交音频。页面可切换“音频转写”“图片检测”或“文本生成”：ASR服务区读取Agent管理状态，图片区保留Vision Worker状态，在线页面读取独立`/api/llm/status`。LLM在线逻辑在API进程中，不增加第六个受管模型服务，也不会启动远程引擎。

服务在后台运行，关闭执行启动命令的 PowerShell 窗口不会停止服务。查看本次受管实例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\status-platform.ps1
```

只停止ASR时，可点击服务管理区“停止 ASR”并等待“未启动”；也可执行以下命令并持续查询直到确认退出。它停止接收/领取新音频，等待当前任务按原规则结束，API、页面和Vision继续运行：

```powershell
& $projectPython -m backend.modules.agent.agent_cli stop
& $projectPython -m backend.modules.agent.agent_cli status
```

停止整个平台时，先等待需要保留的图片任务完成，或显式取消后等待状态更新，再执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-platform.ps1
```

停止命令只请求本项目管理器停止自己创建的实例，经Agent排空并确认ASR子进程退出后，再关闭其余入口；不会按进程名称批量结束Python/Node，也不删除任务、音频、图片或模型。Python管理入口启动/停止成功退出码为0，失败为2；状态查询“未运行”是正常结果。查看状态时还应阅读`status`和`message`，不能只看查询命令退出码。

独立ASR正常停止不关闭整个平台。管理器仍监督API、投递器、Agent、Vision及页面这些入口；关键入口异常退出会触发整套收尾，但须先取得Agent及ASR退出确认。若Agent已退出却缺少ASR退出证据，管理器保留其余仍运行的服务和锁，不把它们强行一起关闭，也不报告正常停止。当前没有自动重启或未确认会话接管；先保留日志排查，不能通过删锁或修改数据库绕过。任务和结果仍保存在数据库中，恢复时继续受原截止时间及重试次数约束。

如果之前手动启动了服务，一键脚本不会接管它们。应先回到原窗口逐个Ctrl+C，确认退出，再使用一键启动。端口占用或同一数据库已有任一类Worker/投递器时，脚本会提示问题，不自动杀掉占用者。

| 可选参数 | 用法 |
|---|---|
| `-PythonPath` | 三个管理脚本均可指定现有 Python 解释器；默认本机 `project311` |
| `-NodePath` | 启动/环境检查时指定已有 Node，默认 `D:\develop\node\node.exe` |
| `-FrontendPort` | 启动时改变页面端口，默认 5173 |
| `-StartupTimeoutSeconds` | 启动就绪等待，默认 180 秒 |
| `-TimeoutSeconds` | 停止等待，默认 45 秒 |

停止命令的等待预算不是当前音频的执行预算；等待超时仍须查状态，不能据此声称进程已经退出。API端口沿用后台`.env`中的`INFERENCE_PORT`，默认5000。配置修改后应停止并重新启动。脚本不会代替数据库迁移或模型准备，也不是操作系统自动重启服务；机器重启后需要再次启动。

新增简化脚本与CLI复用同一Service：`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\asr-service.ps1 -Action start`（启动ASR）、`-Action stop`（只停ASR）、`-Action status`（查询）。默认等待180秒，可用 `-WaitSeconds 0..600` 调整；超时不等于已停止，也不强行取消音频。Agent异常死亡且旧会话退出未确认时，当前无自动接管/清理，需要保留证据核查，不能删锁或改库。

## 3. 页面操作与课堂演示

### 3.1 音频转写

先在导航选择“音频转写”，使用已有的公开短中文样例：

`D:\1 研究生\aixm\inference-platform\runtime\samples\asr_example_zh.wav`

1. 在“ASR 服务管理”中核对“计算节点”“ASR 实例”和模型版本；节点登记成功不代表模型运行，平台刚启动时ASR应为“未启动”。
2. 从开发目录本地 `.env` 复制 `INFERENCE_AGENT_TOKEN` 的值到“本机管理令牌”密码框，不要发送到聊天。点击“启动 ASR”，等待“可以转写”，再选择样例、Whisper small和中文；也可使用CLI完成启停。
3. 点击“提交转写”，记下任务编号。任务一般经过待投递、排队、转写、已完成；短样例可能在两次页面刷新之间跳过中间显示，这不表示没有经过后台流程。“正在执行”表示模型已加载且忙碌，新提交进入原队列，与“模型加载中”不同。
4. 查看“转写全文”“时间分段”“执行信息”，说明文字来自本机真实模型，模型版本与耗时保存在结果中。复制文字，下载TXT和JSON。服务管理区“当前任务”可跳到该任务详情。
5. 点击“停止 ASR”后等待“停止中”变成“未启动”，完成当前音频后才退出。停止期间禁止新音频提交，已有历史结果仍可读取和下载；停止服务与取消单个任务不同。若提交回执不确定，保留原文件、版本和编号重试确认，后台幂等规则保持。
6. 保持ASR停止，下载历史结果并刷新任务链接，确认URL中的任务编号仍能查询到数据库结果；令牌会清除，需要再次管理时重新填写。切到图片页核对Vision仍就绪，再返回音频页，重新填写令牌并启动ASR，等待“可以转写”。原任务和结果不会因再次启动消失。
7. 演示结束后再次停止ASR，再使用整个平台停止脚本关闭API、Agent、Vision、投递器和页面。关闭浏览器不会取消ASR离线任务或删除结果，也不会替你停止服务。

令牌只在当前页面内存，不写localStorage、sessionStorage、URL或构建配置；切换工作台、节点、实例和离开/刷新页面时清除，也可手动点“清空令牌”。命令返回202只说明后台已受理意图，页面不直接将其当作模型就绪或进程退出；发生409、网络错误或超时时只读核对，不自动重发管理操作，确认当前状态后再手动决定。

页面约每2秒读取管理状态，已收到的观察超过10秒会失效；隐藏或离开页面也放弃旧的可用状态，恢复后重新查询。这个有效期不是Agent心跳超时，更不能证明服务已停止。“停止未确认”“状态未确认”和“未启动”含义不同：前两者不能宣称退出或重新启动替代实例。服务管理区仍显示模型最近错误；离线时不把旧任务报告显示为实时任务。

取消功能保留：待执行任务可直接取消；执行中先显示“取消中”，确认停止或执行权到期后进入“已取消”。短样例结束很快，来不及取消而返回“已结束”是合法结果，不要为了演示修改数据库状态。ASR-3A历史浏览器记录不含再次启动或执行中排空；本轮是否通过这些场景须看ASR-3B实际证据。

要演示在途停止及后续队列保留，按[ASR独立启停说明](ASR独立启停说明.md)中“演示当前任务做完再停”的步骤操作：先用现有44.3735秒重复样例让任务A进入执行，再提交B并确认排队后停止。A按原规则收尾，B保留原截止时间；再次启动不会给B重新计时，过期可能失败。不要把“停止服务”理解为“取消全部任务”或“暂停任务期限”。

公开样例约 5.55 秒，仅用于链路验证。模型原文可能含专有名词错误，需要人工校对；这不是准确率测试集，也不能用一次样例耗时推出平台并发吞吐。

一次任务可以这样讲给老师听：**页面提交音频；API 校验输入并保存文件；M05 在同一事务保存任务、提交编号和待投递事件；M08 将事件投递给 M07；M12 Worker 主动领取通知，再申请有效执行租约；受管子进程调用 Whisper；结果先写入数据库，再确认通知；页面查询结果并生成下载文件。**

文件、任务和通知各司其职：音频或图片文件保存“要处理的内容”；任务档案保存“现在的状态、执行权和结果”；通知只告诉 Worker“有任务可领”。重复通知不是新的执行许可，仍须经过租约检查。

### 3.2 图片检测

在导航点击“图片检测”，或直接打开 **<http://127.0.0.1:5173/?type=vision>**。复跑现有公开样例时选择：

`D:\1 研究生\aixm\inference-platform\runtime\samples\yolo-bus.jpg`

1. 等待顶部“图片Worker”显示就绪，选择一张图片。页面给出预览及有效限制：静态JPEG/PNG、最多10MiB和20,000,000像素。预览不是最终解码验证，后台仍会检查完整文件、方向与像素。
2. 核对“检测模型”下的准确版本`yolov5n-v7.0-onnx`。初次演示保留置信度0.25、重叠阈值IoU 0.45、最多目标数100，然后点“提交检测”。置信度越高通常保留目标越少；阈值必须大于0且不超过1，目标数必须是1—300的整数。
3. 获得任务编号后等后台执行，任务列表与详情自动更新。已受理任务由后台处理，切换工作台或关闭浏览器不会取消它；取消请使用详情中的“取消任务”，等待后台确定结果。
4. 成功后先显示“原图”，点击“检测框图”查看框和类别。公开公交车样例本次得到3个人和1辆公交车，但这不是任意图片的准确率保证。
5. “检测目标”列出类别、置信度和原图像素坐标。坐标原点在归正后原图左上角；页面缩放不改变坐标。表格保留两位小数，JSON保留原始数值。手机上可在表格内部左右滚动；“执行信息”显示版本、CPU设备与参数。
6. 点击“下载JSON”或“下载框图PNG”。框图读取既有后台图片接口，使用已经保存的检测JSON绘制；下载不会重新运行YOLO。读取失败会单独提示，可重新读取，不要反复提交新任务。
7. 刷新后，`?type=vision&task=任务编号`恢复同一结果；切回ASR和图片也保留各自选中的任务。同一页面内保留已选文件，整页刷新不会恢复尚未确认提交的文件/幂等编号。原ASR的`?task=任务编号`链接保持兼容；把图片编号放到ASR链接会提示类型不匹配。

没有检测到目标时，页面显示“检测成功，本次没有发现目标”。它仍有合法JSON和没有框的结果PNG，表示当前模型与阈值没有保留目标，不等于上传失败。复跑本轮空检测可选`runtime\verification\part9\blank.png`。

如果提交响应不确定，保留当前文件和参数，用“重试提交”复用原编号；改变参数/文件会开始新提交。格式签名不符或字节超限的图片会在页面拒绝，完整解码错误仍由后台提示。模型目录禁用只影响新任务，旧结果继续读取。完成全部演示后再统一停止平台。

图片后台沿用`POST /api/tasks/vision`和独立`vision.yolo-general`通知队列。命令行接口用法见[接口说明](接口说明.md)。归正原图/按需框图不是新的对象存储产物服务，原受管输入必须保留。

### 3.3 在线文本入口

选择“文本生成”，或打开 **<http://127.0.0.1:5173/?type=llm>**。当前默认显示“尚未配置大模型服务”，没有可用在线模型，“开始生成”禁用。这是如实反映配置，不是页面故障；音频和图片仍可正常使用。无需为使按钮可点而填写虚假地址或登记测试模型。

将来实际服务配置并登记后，选准确模型版本、输入文本，核对温度与最多输出token，再点“开始生成”。当前页面是单次纯文本请求，不是保存整段聊天历史的聊天系统。增量文字会逐步显示，可以复制或下载TXT；中断后下载只含已收到部分，并在文件名加`partial`。token数与汉字数不同，后台`outputCharacters`也不是模型token计数。

在线请求依赖当前连接。点击“停止生成”、隐藏/离开页面、切换工作台时会中断读取并尝试通知后台停止；不要把它类比为ASR/图片关闭页面仍继续的离线任务。停止回执与远端引擎停止确认分开，`释放未确认`需要服务端核对。网络错误后按原请求编号查状态，不自动重新生成或把新回答接在旧回答后。

`?type=llm&request=在线编号`刷新仅恢复生命周期元数据，不能恢复输入或回答正文；页面不将正文写入localStorage。需要留存当时内容时在刷新前自行下载。服务端记录也只保存状态、时间、版本、字符计数和安全错误，不保存聊天正文、密钥或endpoint。配置与未确认许可维护见[模型管理说明](模型管理说明.md)第6—7节。

## 4. 五个窗口手动启动（排障备用）

每个后台窗口都先执行第1节的目录和`$projectPython`两行，再分别运行下表的一条命令。每条都是持续运行的程序，不能将五个启动命令粘在同一个前台窗口里期待全部启动。

| 窗口 | 命令 | 作用 |
|---|---|---|
| API | `& $projectPython -m backend.modules.api.run` | 接受上传、查询和取消请求 |
| 投递器 | `& $projectPython -m backend.modules.dispatcher.task_dispatcher` | 首次投递、失败补投、有限重试与到期恢复 |

## 5. 环境、配置与模型准备

核对解释器和依赖，默认不安装：

```powershell

& 'D:\develop\node\npm.cmd' --version
& $projectPython -m backend.modules.asr.prepare_model --check

```

两个`prepare_model --check`仅读取本地模型清单和文件，核验固定权重大小和SHA256，不联网。模型目录分别为 `runtime/models/whisper-small` 和 `runtime/models/yolov5n-onnx`；准确版本见[接口说明](接口说明.md)。环境检查现在同时核对两类依赖与模型文件。实际Worker启动还会加载模型；“文件完整”与“模型加载成功”是两项检查。

配置来源依次为：进程环境变量 > 开发目录`.env` > 代码默认值。CLI管理和默认推理配置可按默认值运行；HTTP启停写操作需单独配置 `INFERENCE_AGENT_TOKEN`（32—256字符），请求使用 `X-Management-Token`，不要在聊天或日志中输出真实值。这不是完整平台鉴权。覆盖设置时参考[env.example](../env.example)，不要覆盖已有`.env`。相对路径按`inference-platform`解析。两类都只使用CPU：ASR配置int8，Vision为固定FP16输入的ONNX；不能仅改为`cuda`就声称完成GPU接入。

LLM四项身份/地址配置默认不填，具体含义与准确规范登记见[模型管理说明](模型管理说明.md)第6节。下面的保护配置即使存在，也不会自动启用LLM：

| 配置后缀（统一前缀`INFERENCE_LLM_`） | 默认值 | 允许范围与用途 |
|---|---|---|
| `MAX_CONCURRENT_REQUESTS` | 1 | 1—4，单静态实例在线许可数，非GPU容量结论 |
| `ADMISSION_WAIT_SECONDS` | 2 | 0.1—10秒，许可有限等待 |
| `CONNECT_TIMEOUT_SECONDS` | 5 | 0.1—30秒，连接/写入/连接池等待预算 |
| `READ_TIMEOUT_SECONDS` | 30 | 0.1—120秒，等待下一网络数据块的预算 |
| `TOTAL_TIMEOUT_SECONDS` | 120 | 0.1—600秒，本次完整在线请求总期限 |
| `SLOW_CONSUMER_SECONDS` | 5 | 0.1—30秒，输出缓冲满后容忍慢客户端的时间 |
| `LEASE_SECONDS` | 15 | 3—60秒，后台处理权存活期限，不是远端停止证明 |

HTTPX2分别提供连接、读取、写入和连接池超时，读取超时针对等待下一块数据，不是整条生成的总时长。本项目另设固定总期限与监督逻辑，不能为了长输出直接关闭全部超时。[HTTPX2官方超时说明](https://pydantic.dev/docs/httpx2/advanced/timeouts/)

默认库只保存在线元数据。服务停止时会对活动在线连接请求取消；对于通用HTTP模型服务，不能据本地API退出就认定远端计算停止。若记录成为`uncertain`，保持占位并按[人工核对流程](模型管理说明.md)处理；不要通过修改SQLite、删除记录或增大并发数绕开核对。

## 7. 常见问题按顺序排查

先记下页面的任务编号、错误码和 `requestId`，再看 API 健康、运行状态和对应日志。不要一遇到问题就删除数据库或重新下载模型。

| 现象 | 先检查什么 | 下一步 |
|---|---|---|
| 启动脚本失败 | 环境检查输出、本次实例日志 | 修复失败项后再启动；脚本不会自动装包/迁移 |
| 5173 无法打开 | 管理状态、Vite 日志、端口 | 确认前端已运行，URL 与 `-FrontendPort` 一致 |
| 页面能开但接口断开 | 5000 健康接口、API 日志 | 启动 API；手动模式改过端口时修正前端代理 |
| health 正常，任务列表却 503 | `alembic current/check` 与 API 日志 | 停止服务、备份、执行迁移；health 不检查表结构 |
| `created` 长时间不变 | `/api/runtime` 的 dispatcher | 启动或修复投递器，它负责首次投递与到期恢复 |
| `queued` 长时间不变 | 对应实例是否在线、模型是否就绪 | ASR查服务管理区与`agent.log`，图片查`visionWorker`/`vision-worker.log` |
| 启动/停止按钮不可点 | 令牌长度、Agent是否在线、当前管理状态 | 先填本机管理令牌；未知、停止中、停止未确认时等待或核查，不强行绕过 |
| `AGENT_UNAUTHORIZED` | 本地`.env`中的管理令牌与输入值 | 重新复制正确值，不在聊天中贴出；失败不会自动重发 |
| `AGENT_COMMAND_STALE` | 另一次命令或Agent会话变化 | 页面先GET核对，确认当前状态后再手动操作 |
| `PREVIOUS_SESSION_UNCONFIRMED` | Agent重启前的模型会话缺少退出确认 | 保留旧会话和日志，不启动替代进程；当前没有自动接管/清理入口 |
| `MANAGEMENT_OBSERVATION_EXPIRED` | 浏览器是否超过10秒未收到有效管理状态 | 等待或点“刷新服务状态”，它是页面观察失效，不是后台停止证明 |
| “停止未确认”或`ASR_STOP_UNCONFIRMED` | Agent日志、受管会话和退出证据 | 保留锁与记录，不启动替代实例、不删锁或改库 |
| `MODEL_NOT_READY` / `MODEL_INVALID` | 模型目录和 `prepare_model --check` | 核对路径、清单与权限，确需修复才显式准备模型 |
| `VISION_MODEL_NOT_READY` / `VISION_MODEL_INVALID` / `VISION_MODEL_WARMUP_FAILED` | Vision模型检查及`vision-worker.log` | 核对固定模型、依赖和本机权限，未就绪前不接图片任务 |
| 图片模型列表为空 | 是否查询`taskType=vision`，已登记/启用/default是否完整 | 省略类型默认只查ASR；用模型维护命令核对目录 |
| 图片成功但没有目标 | 任务状态及空检测提示 | 这是合法结果，可下载JSON/PNG；先核对图片和阈值，不把空结果当服务失败 |
| 图片JSON有结果、读取框图失败 | 输入完整性、结果状态、图片访问错误码 | 框图依赖受管原图和已提交JSON；不是再次推理，勿删除原始图片 |
| `WORKER_ALREADY_RUNNING` / `DISPATCHER_ALREADY_RUNNING` | 原窗口/受管实例是否仍在运行 | 使用已有实例或正常停止，不删除锁文件绕过保护 |
| 上传报400/413/422 | 错误码、文件实际内容与对应类型限制 | ASR默认20MiB/300秒；图片默认静态JPEG/PNG、10MiB/20,000,000像素 |
| 429 在途已满 | 是否积压非终态、Worker/投递器是否正常 | 等待执行或取消不再需要的任务，不连续重新提交 |
| 提交超时、页面提示结果不确定 | 任务列表和原提交编号 | 同页保留原文件/参数，用“重试提交”复用编号 |
| `retry_wait` 或 attempt=2 | 任务错误、剩余期限、运行状态 | 暂态失败在有限预算内重试；父 Worker 退出仍需重新启动服务 |
| `QUEUE_TIMEOUT` / `TOTAL_TIMEOUT` / 最终失败 | 对应期限和错误 | 修复根因后确需重做，用“提交新任务”；旧任务不会无限重跑 |
| 取消仍为“取消中” | Worker 状态、数据库与 worker.log | 等待控制检查；无法确认进程结束会保留槽位并报错 |
| `WORKER_STOP_UNCONFIRMED` | 受管停止日志和进程状态 | 暂停新任务，保留日志排查；不要启动第二 Worker 或删锁 |
| SQLite 锁忙/无法写入 | 磁盘空间、目录权限、是否有长时间占用数据库的工具 | 关闭自己确认的占用工具，保留数据，恢复后用原提交编号重试 |
| 重启后任务看不到 | 启动目录、`.env`、进程环境变量 | 核对是否连接了同一个数据库和 uploads 配套目录 |

手动模式修改 API 端口时，可将 `frontend/env.example` 复制为 `frontend/.env`，设置 `INFERENCE_API_TARGET=http://127.0.0.1:实际端口`，然后重启前端。它与后台 `.env` 是两个配置文件。Vite 只接受本机回环代理目标，不应改为公开服务器。

只读检查常用端口，不自动结束占用进程：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 5000,5173,4173 -ErrorAction SilentlyContinue | Select-Object LocalAddress,LocalPort,OwningProcess
```

若要识别某个占用者，将实际 PID 填入 `$ownerProcessId`，只读查看路径和命令行，再决定是否回到自己的窗口停止：

```powershell
$ownerProcessId = 12345
Get-CimInstance Win32_Process -Filter "ProcessId = $ownerProcessId" | Select-Object ProcessId,CreationDate,ExecutablePath,CommandLine
```

| `runtime/logs/platform/<实例编号>/` | 一键管理器启动的组件标准输出/错误，便于定位早于业务日志初始化的错误 |
| `runtime/platform/` | 管理器实例身份、状态与锁；不是业务数据库 |

## 9. 首版边界

当前保持Windows、CPU、SQLite、本地受管文件与通知队列，ASR和Vision各1个执行槽位。ASR由本机Agent唯一管理，运行管理器不等于操作系统守护或多节点资源调度。未要求停止时，仍存活的Worker可按原规则重建故障模型子进程；停止意图生效后不为接续任务重建。Agent异常退出留下未确认会话时，当前保守阻断，没有自动接管、清理或恢复按钮；实际验证状态以阶段记录为准。

M08可恢复离线任务状态，但依赖投递器和数据库可用；租约到期不证明旧计算已经停止，真实资源释放仍需进程确认。ASR/图片与在线活动请求共享最大在途20，各期限是开发规则，不是容量承诺。第十二部分实现在线接口与页面，真实LLM模型、引擎取消/GPU释放尚未验证。没有账号认证、GPU、多节点、Redis/外部对象存储、生产托管或公开发布；原架构资料描述的其他能力应与实际实现表分开讲解。

演示前可以自问三个问题：任务受理与任务成功有什么区别？领取通知后为什么还要申请租约？关闭网页、取消任务和停止 Worker 分别会造成什么结果？

受管上传对象写入后不可手工改写；当前完整性检查会拒绝静态内容篡改，但不保证外部本地进程在哈希校验与解码两次读取之间并发替换对象的情形。
