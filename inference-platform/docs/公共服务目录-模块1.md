# 公共服务目录（模块 1）

本模块在原平台中增加“服务管理”入口，统一维护 ASR、YOLO、LLM 接口资料。当前仍使用原任务与 SQLite 队列；公共执行、Redis、API Key 与后台进度采集将分模块接入。

## 使用前提

新增迁移 `20261020_0015`，只增加五张目录表，不修改旧任务、许可或模型记录。**当前日常 API/Vite 正在运行，本轮不替用户中断会话或升级日常库。** 新页面需要在备份、迁移和正常重启 API 后使用；旧进程可能返回 404，未迁移新 API 返回 `CATALOG_STORAGE_UNAVAILABLE`。

采用项目已有 Python 3.11 环境，正常停止平台并核对在途/未知调用后，将数据库、上传目录及数据库旁 `*.asr-services.json` 配置文件成套备份并校验，再在项目目录执行：

```powershell
python -m alembic upgrade head
```

本模块不自动新建表、不改写 `.env`，启动和刷新也不会自动导入服务。已有目录资料时拒绝降级删除；出现问题使用备份核对或前向修复。

## 页面操作

1. 点击主导航“服务管理”，添加服务，选择 ASR、YOLO 或 LLM。
2. 填写逻辑服务编号、名称、平台模型编号与协议。上游版本可留空；目录修订只表示连接配置身份。
3. 添加实际调用目标，填写根地址、调用路径、健康路径与上游模型名。一个服务最多八个目标。
4. 共用 GPU 或服务池时，先在下方登记共享资源组，再填写目标的共享组编号；一个目标可引用多个组。额度 1 是保守默认，较大额度启用前需填写获准容量依据。
5. 声明设备资料及可选监控能力。没有接口时选择“服务未提供查询接口”，进度和实际设备均不编造。
6. 保存草稿，针对保存的修订显式执行连接测试。编辑草稿后旧测试不能用于启用新修订。
7. 五分钟内所有启用目标的连接测试通过，且没有阻断问题时，可“启用目录修订”。这只是目录选择，**不启用当前任务执行**；页面始终显示“公共执行未接入”。

固定策略仅允许一个目标勾选启用；GPU 优先可保存多目标，但启用前需要设备、兼容性及共享组依据。无目标、异步缺少完成/结果接口等问题在页面显示。保存新草稿不会覆盖旧已选目录修订；明确启用后才改变目录选择。停用不清除历史修订。

“导入已有 ASR 配置”显式读取 v2.13 配置文件，复制为未启用的目录资料；已有同编号服务跳过。原文件、选用状态、旧模型登记和任务均不改变。不会把未知设备自动登记成 GPU。

## 协议与检查边界

| 协议 | 服务类型 | 默认路径/健康成功依据 |
|---|---|---|
| `remote-v2` | ASR | 沿用 `/api/v1/asr/health`，核对 `success=true`、`status=ok`、`model_loaded=true` |
| `openai-audio` | ASR | `/v1/models` 返回的模型列表包含所填上游模型名 |
| `vision-json-v1` | YOLO | `/health` 返回 `status=ok`、`modelLoaded=true` 且 `model` 匹配；推理适配器在模块 4 实现 |
| `chat-completions-sse` | LLM | `/v1/models` 模型列表匹配；公共多目标流式调用后续接入 |

每次手动测试只发一个有界 GET：总时限五秒、响应至多 64 KiB、不跟重定向、无业务文件。健康通过不证明任务完成、模型推理、设备绑定或容量。

凭据只填写环境变量名；实际值在测试时由配置层读取。默认校验 HTTPS 证书，可指定 CA 或准确 HTTPS Origin 例外，两者不能混用。响应与记录只包含错误类别，不回传凭据或上游原始正文。

监控配置目前是**声明**：`none` 或后续参考协议 `job-json-v1`。查询路径必须只包含一个 `{requestId}`，例如 `/jobs/{requestId}`，结果路径例如 `/jobs/{requestId}/result`；可声明进度和实际设备能力以及 5—60 秒间隔。模块 4 才实现查询器和参考响应契约；不因填了路径就开始轮询或声称接口已验证。

## 本机管理 API

前缀 `/api/admin/service-catalog`；仅本机 Host/来源/连接允许，写入须 `application/json`。本阶段不是校园网公开 API，API Key 在模块 5 实现。

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/services?page=1&pageSize=20` | 分页目录，最大每页 100 |
| GET | `/services/{serviceId}` | 草稿、已选修订、检查、问题及 `executionReady=false` |
| PUT | `/services/{serviceId}` | `{config, expectedVersion}`；首次版本为 null，更新使用读取的版本 |
| POST | `/services/{serviceId}/activation` | `{expectedVersion, revision, enabled}`；只选择目录 |
| POST | `/services/{serviceId}/targets/{targetId}/test` | `{expectedVersion, revision}`；手动健康 GET |
| GET | `/resource-groups?page=1&pageSize=100` | 分页共享组资料 |
| PUT | `/resource-groups/{groupId}` | `{config, expectedVersion}` |
| POST | `/import-asr` | `{}`，显式导入 |

GET 只读数据库，不访问服务、不重发、不选设备。保存/启用采用版本冲突检查；409 后刷新目录，重新选择服务，再应用保留的草稿。检查进行期间如配置已变化，迟到结果不能更新新修订。

## 存储

`inference_services` 保存草稿/已选指针与版本；`inference_service_revisions` 保存不可变快照；`inference_resource_groups` 保存共享组资料；`inference_target_checks` 保存每修订目标最新健康检查；`inference_catalog_events` 保存目录保存/启停/检查事件，关键事件与操作同事务。

这是目录事件，不是旧任务的详细日志。任务时间线与业务状态同事务将在模块 2 实现，上游监控快照在模块 4 实现。实施顺序见[总计划](统一推理中转平台-实施计划.md)。
