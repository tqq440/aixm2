# 分布式通用AI推理与算力调度平台开发周报

汇报周期：2026年10月12日至10月18日；统计截至10月17日。下周计划对应10月19日至10月25日。

本周完成了本机 CPU ASR 从服务启动、音频上传、任务执行到结果下载、停止和再次启动的完整流程，并完成课题组外部 ASR 的适配代码与隔离测试。当前重点转向真实服务联调；GPU 自动分配及 GPU 满载时由 CPU 承接小任务，仍属于后续调度目标。

**一、本周目标、开发模块与工时**

项目总体目标是建立可接入不同模型的推理与算力调度平台：统一接收请求、保存任务、控制并发，并根据模型能力和真实资源情况选择执行实例。后续优先使用合适的 GPU；GPU 没有可用容量时，允许支持 CPU、规模合适且满足处理时限的小任务由有余量的 CPU 实例执行。

本周先以 ASR（语音转文字）验证完整流程，形成可以在笔记本上演示和继续扩展的基础。

**二、遇到的问题、处理办法与需要课题组讨论的事项**

| 问题 | 处理办法与当前状态 | 是否需要课题组协助 |
|---|---|---|
| 整个平台停止时，Windows 停止信号提前中断正在转写的模型 | 对模型子进程进行控制台隔离，保留进程管理约束；重新验证在途任务结束、模型退出和平台重启，已修复 | 暂不需要；[修复与真实复验记录](阶段记录/ASR-2B-独立启动与安全停止-验收记录.md)已保存 |
| 停止过程中，错误报告可能覆盖“停止中”状态 | 修复状态更新规则，保留已生效的停止意图；54项相关回归通过 | 暂不需要 |
| 外部调用断线后，无法确认远端是否仍在执行，重发可能导致重复计算 | 保存调用事实；结果不明时阻止自动重发并保留占位，重启也不清除。防护已实现并隔离验证；真实远端行为待联调 | 需要确认异步任务查询、提交响应丢失时的找回/去重规则，以及是否有取消能力 |
| 课题组服务尚未连接成功 | 已对指定服务端口进行检查，均停留在 TCP 超时阶段，未进入 TLS 或模型检查。最新网络条件为尚未连接校园网，等待校园 VPN 连接后继续 | VPN 连通后如仍超时，需要服务方确认服务在线、端口开放及可访问网段；暂不能判定服务故障 |
| “按资源选择 GPU、满载后小任务转 CPU”缺少可执行的资源与设备接口 | 已明确目标，尚未实现调度；接口中的 device_id 含义未说明，不能直接当作 GPU 编号使用 | 需要明确可用设备、资源状态来源、设备选择方式、CPU 兼容性、允许并发数和小任务判断标准 |

建议课题组集中确认三件事：**平台如何选择执行设备，如何取得可信的资源余量，以及异步请求异常后如何确认是否已经执行。** GPU“满载”和“小任务”的阈值应结合模型显存需求、执行槽位、CPU余量及实际耗时确定，避免只按单一利用率或文件大小判断。

本周收到的接口文档支持“异步提交取得 task_id，再查询状态和结果”；当前适配器仍使用同步协议。切换异步时需要保存平台任务与上游任务编号的对应关系，并处理查询失败、重启恢复和提交响应丢失，复用现有任务状态规则。接口差异及待确认项见[ASR服务对接清单](ASR服务对接清单.md)。

**三、下周具体计划、目标进度与预期成果**

下周优先完成课题组真实 ASR 调用联调，同时明确资源调度的接口和判定依据。以下为周计划，按条件逐项推进，不承诺在硬件和管理条件未明确时完成 GPU 自动调度。

| 优先顺序与模块 | 具体工作 | 计划达到的进度与交付成果 | 所需条件 |
|---|---|---|---|

| 2．M12 外部 ASR 异步适配方案 | 确认上游 task_id、查询状态、异常恢复和去重语义；明确同步转异步的改动范围 | 先交付接口对照与异常场景清单；方案确认后实现异步提交、编号持久化和轮询，覆盖成功、失败、查询超时及恢复路径 | 服务方确认协议；实现范围确认后开展，不将方案写成已实现 |
| 3．M09/M10 资源与调度规则准备 | 收集 CPU/GPU、显存、资源采集和设备绑定信息；明确 GPU 优先、适合的小任务由 CPU 承接、其余排队的条件 | 形成资源字段清单、设备选择约定和调度决策表，列出需要实测的阈值 | 课题组提供可用资源与管理范围；本项先形成方案，不宣称真实 GPU 调度完成 |
| 4．兼容回归与交付记录 | 随实际改动验证本机 Whisper、历史结果、任务规则和页面，整理实际结果与未解决项 | 交付联调报告和操作说明；ASR-4B获准范围完成后集中同步 Multica，用户验收单列 | 真实调用与对应检查完成；未完成时只更新本地阻塞记录 |

若校园 VPN 或服务条件仍未具备，下周先交付协议差异、异常测试场景及资源调度规则草案，真实调用继续标为待条件，不使用模拟输出替代实际结果。

ASR-4B 完成后的下一部分是 **ASR-4C 远端受管启停**，目标为平台能够启动服务、确认模型就绪、停止并确认退出。需要部署材料、管理权限或可信管理接口，并明确服务是否共享及唯一管理者；条件具备且该部分获准后再实施。YOLO/LLM 新功能、多节点自动调度和容量压测暂不列为下周必达项。
