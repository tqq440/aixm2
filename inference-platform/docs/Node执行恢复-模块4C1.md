# Node 执行身份与结果恢复（模块 4C1）

> 后续增量：4C2 已增加实际 HTTP/媒体/SSE 适配、可选查询、后台采集和执行器，业务开关默认关闭。见[4C2说明](业务协议与监控-模块4C2.md)。本文“没有生产适配器”“后续4C2”等保留4C1交付时点含义。

这一部分先解决“中心交给 Node 的是不是同一次调用、重启后能不能避免重做、结果如何回到中心”。原 4C 拆为 4C1 和 4C2，原计划范围不减少。

**4C1 提供内部执行与结果恢复边界，真实业务 HTTP 适配器尚未接入。普通 Node 启动没有适配器，会明确拒绝新执行。** 测试通过专用应用工厂参数注入隔离替身，不能据此声称真实 ASR、YOLO 或 LLM 已接通。

## 调用过程

1. 中心复用公共调度和容量事务，选择目标并预约应用、目标及全部共享组额度。这次新增的桥接层不再预约一遍。
2. 中心读取 Node 已保存的就绪快照。Node 编号、服务、模型、配置修订、启动实例、门禁及适配协议都要符合条件。
3. 中心把本次 Node 执行身份保存在自己的 SQLite，再将公共调用标记为开始发送。此后不能通过重复派发再次 POST 推理。
4. Node 校验独立中心执行凭据，在自己的 SQLite 中先保存调用与“发送中”事件，再调用适配器。网络调用不占 SQLite 写事务。
5. 适配器取得可信终态后，Node 先保存结果和事件，中心再验证原任务约束并保存结果、结算额度和事件。
6. 原队列模块的内部 `QueueService.run_once_node()` 复用相同轮询和结算后确认流程，对接 Node 桥接。4C1 没有另建队列，也没有提前确认通知的捷径；普通队列维护 CLI 不会自动开始推理。

Node 调用编号全库唯一。同编号、同执行内容只返回已有记录；不同次数、实例、修订、输入指纹或目标会产生冲突。Node 重启后，原“发送中”变成“结果未知”，不会扫描档案重新推理。已保存的结果保持可取回。

## 服务配置关联

中心目录 `ServiceTarget` 新增可选 `node`，包括 `nodeId`、Node 本机 `serviceId`、`configRevision`、Node 根地址 `baseUrl`、中心进程内凭据环境变量名 `executorTokenEnv`。保存后随中心不可变修订一起固定；没有 Node 关联的旧目标保持旧格式与指纹。

目标原来的 `baseUrl`、`invokePath` 仍表示真实业务地址，继续用于容量身份。不能把多个 Node 地址当成同一业务的额外并发。共享 GPU 的不同服务仍须引用相同资源组；这里管理并发许可，不管理内存或显存。

Node 的 `modelId`、`kind` 须与中心逻辑服务一致。每次派发另行固定当时的 `instanceId`。4A 的 `catalogServiceId/catalogRevision` 仍是关联资料；不要求中心内容哈希与包含其引用的 Node 内容哈希相互相等。有效执行由中心内部授权、固定中心修订和固定 Node 修订共同约束。

目录会列出 `NODE_PROTOCOL_ADAPTER_PENDING` 接入问题，`executionReady` 继续为 false。页面编辑 Node 关联、运行执行器及真实协议配置在后续模块交付。

## 凭据和内部接口

独立 Node 环境支持 `NODE_EXECUTOR_TOKEN`，32—256 个非空白 ASCII 字符，必须与管理、观察及每个业务上报凭据不同。中心在 `executorTokenEnv` 指向的环境变量中保存对应凭据。只登记变量名，不在目录、数据库或日志中保存密钥。

| 接口 | 本轮行为 |
|---|---|
| `GET /node/internal/v1/services/{id}/execution-availability` | 读取 Node 缓存门禁和适配器声明，不查询业务 |
| `POST /node/internal/v1/executions` | 执行身份及适配边界；默认无适配器返回 503 |
| `GET /node/internal/v1/executions/{id}` | 只读执行档案，不带结果正文 |
| `GET /node/internal/v1/executions/{id}/result` | 读取已保存结果，不查询或重做业务 |

这些接口只接受中心执行凭据。管理、观察、业务上报和未来应用 API Key 都不能直接派发。执行凭据也不能管理服务或伪造业务心跳。所有 GET 只读本地数据。

请求仍限 16 KiB，只传调用编号、执行次数、中心修订、Node 修订、实例、目标、协议、期限及不透明输入编号/指纹。`inputRef` 是中心请求归属编号，不是文件路径、下载地址或实际媒体内容。本轮不传输文件、聊天正文或 token 流。

Node 结果 JSON 上限 2 MiB；中心 HTTP 客户端响应上限 3 MiB，默认有界 10 秒，不跟随跳转、不读取代理环境、不自动重试 POST。自定义超时最多 900 秒，但具体业务超时和租约续期应由 4C2 执行器管理。TLS 使用系统验证，不复用业务目标的 TLS 例外；生产证书与网络隔离在模块 6 核验。

OpenAPI 快照为 `docs/node-foundation.openapi.json`。应用工厂参数 `execution_adapter` 是开发用适配端口，要求声明 `protocols` 并实现 `execute(ExecutionCommand) -> AdapterOutcome`。输入完整性、实际业务协议、终态证据及流结束验证是后续具体适配器的职责；普通异常一律视为未知。

## 结果与异常规则

| 情况 | 处理 |
|---|---|
| Node 已保存结果，响应丢失 | 中心保留未知占位；显式取回原调用结果，只 GET，不重新 POST |
| Node 仍发送中或结果未知 | 不释放额度，不换目标、不重发 |
| Node 报告成功，结果未取到 | 记录结果待获取，平台不成功、额度不释放 |
| 取得有效最终结果 | 按原 ASR/检测/在线完成约束验证，与中心状态、事件、额度在同一事务保存 |
| 已超过租约或期限才取回 | 保留原失败/超时历史，单独保存迟到结果，记录核对终态，幂等释放未知额度 |
| 人工已确认同一终态，随后取回结果 | 补存迟到结果，不重复释放；冲突终态拒绝覆盖 |
| 404、429、超时、跳转、格式错误 | 无可信终态，不能当成停止或释放依据 |
| 日志或结果数据库异常 | 不靠重新推理恢复；结果事务失败可再取回，SQL 异常正文和绑定参数不进入运行日志 |

ASR 结果沿用原语言、时长和分段限制；检测结果仍保留旧本地 YOLO 模型、类别和指纹约束，不能冒充任意远程 YOLO 已兼容。在线结果只保留完成原因与字符数，不存聊天正文；真正的 SSE 转发与结束信号验证留 4C2。

`NodeInvocationBridge.snapshot()` 只读中心数据；`fetch_result()` 是显式维护/后台核对操作，不应挂在公共 GET 请求中。快照区分远端状态、结果待取、平台终态和迟到结果。自动监控、实际设备证据、进度合并与退避在 4C2；本轮不推算进度，也不把分配 GPU 说成模型已加载。

## 与主机控制的联动

有 `sending/unknown` 执行档案时，停止、启动切换和升级后台流程会阻塞；即使业务报告队列为空、已停止，也不能忽略 Node 未决调用。修改本机配置、容器资料或更换手工启动实例同样被保护。Node 实际派发还会永久标记本次实例可能已接单，升级回退不能再声称它从未接过任务。

Node 没有待执行任务队列：这里是已发送调用的恢复档案；业务内部排队仍由业务服务实现，中心额度继续占用到可信终态。

## 迁移与使用边界

中心新增 `0018`，只建 `inference_node_dispatches`；Node 独立新增 `0003`，只建 `host_node_executions`。旧记录不重新绑定、不补造执行日志，两条迁移链分别维护。中心有公共调用历史或 Node 派发记录时，0018 在删除表和移动版本前就拒绝降级；Node 有执行档案也拒绝降级删除，避免丢失去重身份、未知调用与迟到结果。

本轮只迁移隔离测试库，日常库仍在 0014。不要直接对日常环境执行迁移或启用公共执行开关。未来切换须按原计划暂停受理、核对在途、成套备份并正常重启；Node 启动只检查结构，仍需显式 `init-db`，不自动升级。

下一部分 **4C2**：实际 ASR/YOLO/LLM HTTP、文件及 SSE 适配，统一后台状态/进度/设备采集，可信终态和未知调用核对；之后模块 5 公共 `/api/v1`、统一 API Key 与页面，模块 6 Linux/真实服务验收。真实服务缺接口进入接入问题清单，不阻塞公共模块开发，也不修改师兄的服务。
