## 已知资料缺项

- 原后端规范引用的 `0-生命周期规范.mdc` 尚未在项目中找到。不能声称已读取或已经遵循其中未提供的要求。
- GPU 加速兼容性未验证；当前仅有一段短中文样例的 CPU 效果与耗时，不代表多语言、长音频、嘈杂场景、准确率或并发容量。
- 第九部分 YOLO 仅有一张公开公交车样例和纯白图片的 CPU 实测，没有广泛类别、复杂场景、准确率、内存峰值或并发压测；Pillow 预处理不宣称与官方 OpenCV 基准逐像素相同。第九部分JSON/PNG是本地结果文件；第十部分另有图片平台任务与按需PNG读取，第十一部分已接入页面；仍没有准确率或容量压测。
- 本机终端 profile 的 Conda 自动激活在工具环境报错；使用现有 `project311/python.exe` 的绝对路径已验证可运行，没有修改系统 profile。
- 健康检查只验证 HTTP 与 SQLite 连接，不校验迁移版本、模型加载或 Worker。可通过 `/api/runtime` 查看实际报告；它没有 GPU 指标，报告过期不等于确认进程已经停止。
- 首版 Worker 和服务管理器依赖 Windows Job Object，仅在本机 Windows 验证。可用第七部分脚本统一启停，当前ASR由Node Agent唯一管理，API、投递器和Vision仍可使用相应入口；托管实例不能绕过Agent另开ASR Worker。ASR/Vision各1槽、同库合计2槽。
- M08已实现有限重试和过期恢复，但依赖投递器运行和数据库可用；手动模式Worker父进程退出后需手动启动新Worker；受管模式在安全退出条件满足时关闭本实例其他入口；ASR正常独立停止不关闭平台，Agent退出未确认时保守保留其余入口并提示核查，需要重新启动整套平台。Worker仍存活时可重建故障或取消后的模型子进程。逻辑租约到期不证明计算进程已停止，实际槽位由各能力独立Worker锁和进程确认保护。尚无操作系统守护或集群接管。
- 首版固定调用者 `local-user`，尚无账号认证与多用户隔离。上传目录必须与数据库一一配套；共享文件锁串行协调上传持久化与清理，不表示已验证并发容量。
