# 本地图片检测说明

本说明对应第九部分：先在命令行独立验证一张图片的真实检测。它复用项目配置和分层服务；本地命令不会创建数据库任务，也不会自行启用YOLO。第十部分已另外接入图片上传、异步任务与Vision Worker，用法见[接口说明](接口说明.md)；第十一部分已增加图片工作台，操作方法见[使用与故障处理](使用与故障处理.md)；本地命令仍可独立运行。

第九部分已完成开发侧及本机真实模型验证，用户随后要求继续第十部分；历史证据保持不变。公开公交车图片实测得到 3 个 person 和 1 个 bus，纯白图片实测为空检测；证据见[第九部分验收记录](阶段记录/第9部分-本地真实图片检测-验收记录.md)。

## 1. 模型和输入

| 项目 | 本机固定选择 |
|---|---|
| 模型标识／版本 | `yolo-general` / `yolov5n-v7.0-onnx` |
| 权重 | 官方 YOLOv5 v7.0 的 `yolov5n.onnx`，3,981,910 字节 |
| 运行库与设备 | ONNX Runtime 1.31.0，`CPUExecutionProvider`；不使用 GPU |
| 图片库 | Pillow 12.3.0，复用 NumPy 2.4.6 |
| 类别 | 固定 80 类通用物体，输出原始英文类别名；不是任意物体识别或自定义类别训练 |
| 图片格式 | 按文件内容识别的静态 JPEG / PNG；不支持动画、多帧、视频或 PDF |
| 默认文件上限 | 10MiB，即 10,485,760 字节 |
| 默认像素上限 | 20,000,000 像素，即宽 × 高；文件大小合格仍可能像素超限 |
| 默认参数 | 置信度阈值 0.25、IoU 阈值 0.45、最多 100 个框 |

“权重”是模型参数文件，“ONNX Runtime”是运行它的程序库；模型文件准备好和模型真正推理成功是两项检查。此次只补充图片运行所需的 Pillow，沿用原有 ONNX Runtime 和 NumPy，不重建 `project311`。

图片先按 EXIF 方向归正，再转为 RGB；透明 PNG 使用白色背景。输出宽高、坐标和带框图片都以这张方向归正后的原图为准。模型输入为 640×640，使用等比缩放和居中填充；结果在去掉填充后还原到原图像素，不以 640×640 坐标交付。

预处理固定为 `pillow-bilinear-letterbox-v1`。它使用 Pillow 双线性插值，不宣称与官方 OpenCV 预处理逐像素相同；样例结果也不是官方精度评测成绩。该固定 ONNX 文件输出原始候选，项目执行一次按类别的 NMS 去除重复框，不再叠加第二次相同后处理。

## 2. 检查或准备模型

在 PowerShell 中进入开发目录并指定已有解释器：

```powershell
Set-Location -LiteralPath 'D:\1 研究生\aixm\inference-platform'
$projectPython = 'C:\Users\86199\miniconda3\envs\project311\python.exe'
& $projectPython -m backend.modules.vision.prepare_model --check
```

`--check` 检查固定版本清单、模型大小和 SHA-256，不下载、不启动 API、不登记模型，也不等于已经执行推理。默认模型目录为 `runtime/models/yolov5n-onnx`。

仅在需要准备缺失模型时显式运行：

```powershell
& $projectPython -m backend.modules.vision.prepare_model
```

检测命令只接受本地已通过校验的固定权重，缺失或校验不符时返回错误，不在检测过程中自动下载其他模型。若目录已有无法通过校验的文件，准备命令保留原文件并拒绝覆盖；先核对原因，再把 `INFERENCE_VISION_MODEL_DIR` 指向新的空目录准备。

换到其他电脑时，先核对已有环境，按需要安装锁定的 `requirements/vision.txt`，再显式准备模型；当前环境不必每次重新安装。模型来源为 [YOLOv5 v7.0 官方发行资产](https://github.com/ultralytics/yolov5/releases/tag/v7.0)，固定代码提交为 `915bbf294bb74c859f0b41f1c23bc395014ea679`。该版本仓库的许可记录为 [GPL-3.0](https://github.com/ultralytics/yolov5/blob/915bbf294bb74c859f0b41f1c23bc395014ea679/LICENSE)。

下载资产 URL：`https://github.com/ultralytics/yolov5/releases/download/v7.0/yolov5n.onnx`。本机下载后锁定的 SHA-256：

```text
04f0e55c26f58d17145b36045780fe1250d5bd2187543e11568e5141d05b3262
```

这是本次官方来源文件的本地校验值，官方资产 API 未提供摘要；不能称作“官方公布的 SHA-256”。后续准备和检测据此检查文件是否与本次锁定文件一致。

## 3. 执行一张图片

现有公开样例已准备，可以直接复跑；无需启动 API、Worker 或页面：

```powershell
& $projectPython -m backend.modules.vision.detect_image '.\runtime\samples\yolo-bus.jpg'
```

以下把路径替换成你自己的 JPEG 或 PNG 文件：

```powershell
& $projectPython -m backend.modules.vision.detect_image 'D:\图片\example.jpg'
```

不指定输出目录时，每次在 `runtime/results/vision-随机编号/` 建立独立结果目录。也可以指定一个**尚不存在**的目录，并调整本次检测参数：

```powershell
& $projectPython -m backend.modules.vision.detect_image 'D:\图片\example.jpg' --output-dir '.\runtime\results\my-first-detection' --confidence-threshold 0.25 --iou-threshold 0.45 --max-detections 100
```

已存在的目录会被拒绝，不覆盖之前的结果。置信度和 IoU 阈值须大于 0 且不大于 1，框数量为 1—300。提高置信度阈值通常会减少保留框；IoU 阈值控制同类候选的重叠去重，不是模型识别准确率。

正常完成后命令退出，不需要启动或停止后台服务器；需要中断时在该命令窗口按 Ctrl+C。命令行输入本地文件路径是本地验证入口的能力；它不表示将来的 HTTP 接口可以接受服务器任意路径。

成功时标准输出是 JSON、退出码为 0；参数或可预期错误输出包含 `error.code` 和 `requestId`，退出码为 2；Ctrl+C 的退出码为 130。日志默认写入 `runtime/logs/vision.log`，可按编号定位详细原因。出现异常退出时不要把未完整发布的结果当作成功。

## 4. 查看结果

每个成功目录包含：

- `result.json`：模型标识、版本、SHA-256、原图宽高、检测框、设备、运行库和预处理版本，以及加载/推理/总处理耗时。
- `annotated.png`：方向归正后的原图，绘制类别、置信度和检测框。

JSON 使用 camelCase。`detections` 中每项包含 `classId`、`className`、`confidence` 和 `box`；`box` 是 `xMin`、`yMin`、`xMax`、`yMax`，单位为原图像素。左上角是 `(0, 0)`，向右 x 增大，向下 y 增大；坐标可带小数，且不得超出原图范围。

如果输出 `detections: []`，表示本次参数下没有保留目标，依然是成功；带框图会保存为无检测框的原图。它不证明图片中一定没有真实物体。`totalSeconds` 包含解码、加载和前后处理，但不含 JSON/PNG 文件写入；单张图片耗时不代表平台并发、吞吐能力或准确率。

## 5. 配置和常见问题

配置由项目 `backend/config` 统一读取；需要调整时参考 `env.example`，在本地 `.env` 中设置：

| 配置名 | 默认值／含义 |
|---|---|
| `INFERENCE_VISION_MODEL_DIR` | `runtime/models/yolov5n-onnx` |
| `INFERENCE_VISION_CPU_THREADS` | `4`，CPU 推理线程数 |
| `INFERENCE_VISION_MAX_FILE_BYTES` | `10485760`，本阶段可调低 |
| `INFERENCE_VISION_MAX_PIXELS` | `20000000`，本阶段可调低 |

这些是图片检测配置，不影响 ASR 的 20MiB / 300 秒限制。当前阶段不扩展 GPU、额外模型或更大图片容量。

| 情况 | 处理方法 |
|---|---|
| 图片不存在或路径不是文件 | 核对完整路径，用单引号包住包含空格的路径 |
| 不支持格式或图片损坏 | 使用可正常打开的静态 JPEG/PNG，修改扩展名不能转换真实格式 |
| 文件或像素超限 | 缩小图片后重试；压缩文件大小不一定减少解码像素 |
| 模型缺失或校验失败 | 先运行准备检查，再根据提示显式准备；不要把任意同名文件当作已锁定权重 |
| 输出目录已存在 | 使用新的目录名，或省略 `--output-dir` |
| 没有检测框 | 先查看完整 JSON；空检测不是程序故障，可检查图片内容及阈值 |

本地命令不产生视觉任务ID，也不提供查询或取消/重试。第十部分已另行接入图片异步后台；第十一部分已接入图片操作页面，实际验收见[第十一部分记录](阶段记录/第11部分-图片检测操作页面-验收记录.md)。
