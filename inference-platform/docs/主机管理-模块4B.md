# 主机管理：容器控制与资源监控（模块 4B）

在 4A 独立 Node 上增加固定版本容器管理、业务排空/恢复、升级及受控回退、持久操作日志和 CPU/内存/GPU 动态快照。中心 Redis、统一调度、并发额度、结果保存和旧任务链路继续保留；4B 的控制操作记录不是推理队列，不会释放中心容量或改写推理任务状态。

## 本轮可用能力与实际验证边界

- 已实现本机 Docker Engine Unix socket 适配、受控启停/版本切换、故障核对和管理 CLI。Docker 开关默认 false；本机没有 Docker，实际容器启停/升级/回退尚未验收，不能把 DockerFake 记成真实 Docker。
- 已有真实回环 HTTP 的排空/恢复和管理 CLI 验证；业务端为明确的模拟服务，真实 ASR 的接口由师兄按协议接入。
- CPU/内存采用 Linux procfs 或 Windows 系统只读接口，不依赖 psutil；GPU 使用固定 nvidia-smi 查询。笔记本已实际取得 CPU/内存/一块 GPU 指标，和实验室设备、模型执行或并发容量无关。
- 没有实现公共推理中转、中心执行接线、任务结果回传或生产 systemd；分别留 4C/5/6。CPU/GPU 内存和显存管理仍由业务侧负责，指标不用于自动分配资源。

## Node 启动与迁移

新增独立 Node 迁移 `20261021_node_0002`，不属于中心平台迁移链。正常关闭 Node，备份其数据库及环境配置，再显式 `init-db` 升级。旧配置、实例、序号、报告指纹和事件保留；重放升级前最后报告不会刷新新鲜度。已有控制/资源记录时拒绝降级删除。

```bash
# 沿用 4A 的 NODE_ID、管理/只读/各服务上报凭据及独立数据库路径。
export NODE_DOCKER_ENABLED=false
export NODE_DOCKER_SOCKET=/var/run/docker.sock
export NODE_CONTROL_TIMEOUT_SECONDS=3
export NODE_METRICS_ENABLED=true
export NODE_METRICS_SECONDS=5
python -m backend.modules.host_node.node_cli init-db
python -m backend.modules.host_node.node_cli serve
```

Node 的 serve 启动一个后台控制/采样循环；构造应用本身不运行外部动作，GET 不触发采样或 Docker 查询。Node 关闭等待自己的有界后台操作收尾，不向业务容器发停止命令。生产 Linux、Docker 权限、TLS、WSGI 和 systemd 在模块 6 验证。

## 固定版本容器资料

首版管理**服务方预先准备好的容器版本**。服务方负责镜像、模型文件、运行参数、数据卷、GPU 绑定及内存策略；Node 登记固定 containerId/imageId，负责启停和版本切换。不会自动拉镜像、创建/删除容器、执行上传脚本或接受任意 Docker 参数。

各版本须具备：

- 完整 64 位容器 ID，以及 `sha256:` 开头的固定镜像 ID，不接受名字、短 ID 或 latest 标签。
- 标签 `inference.node_id`、`inference.service_id`、`inference.version_id` 与登记一致。
- Docker restart policy 为 no，autoRemove=false；Node 独占生命周期控制，不与其他自动管理器共同拉起。
- 业务启动从 Node assignment 获取当前启动实例，支持 startPaused 和控制协议；运行地址在版本切换后仍须对应同一服务的 internalBaseUrl。
- 逐版本同模型兼容依据；自动回退另需持久数据/队列兼容依据。配置声明不等于已经通过真实验证。

PUT `/node/v1/admin/services/{serviceId}/runtime`，管理凭据，样例：

```json
{
  "expectedControlVersion": 0,
  "config": {
    "versions": [
      {"versionId":"v1","containerId":"替换为完整64位容器ID","imageId":"sha256:替换为64位镜像ID","compatibilityEvidence":"服务方核实的模型与协议说明"},
      {"versionId":"v2","containerId":"替换为另一完整容器ID","imageId":"sha256:替换为另一镜像ID","compatibilityEvidence":"服务方核实的同模型与协议说明"}
    ],
    "drainPath":"/internal/drain",
    "resumePath":"/internal/resume",
    "drainTimeoutSeconds":300,
    "readyTimeoutSeconds":120,
    "exitTimeoutSeconds":30,
    "autoRollback":false,
    "rollbackCompatibilityEvidence":null
  }
}
```

占位 ID 必须替换，实际输入按 Schema 校验。GET 同路径读取控制版本和配置。配置持久化不调用 Docker；正式接管前先核实容器、标签、镜像和业务协议，再显式设置 `NODE_DOCKER_ENABLED=true` 并重启 Node。当前 Windows 只验证适配契约和替身，真实 Docker 适配只面向 Linux Unix socket；不会读取 DOCKER_HOST 或远程 Docker context。

每个服务只能有一个未决操作，同一容器不能登记成其他服务。受管服务的启动身份由控制流程生成，不能使用 4A 手工绑定接口绕过；旧手工实例不会凭自报 stopped 自动取得容器退出证据。改动基础服务资料后需要重新登记运行资料；活跃/未知控制操作阻止配置改写。

## 一键启停与升级

确认 Node 已运行、业务已接入后：

```bash
python -m backend.modules.host_node.control_cli start asr --version v1 --wait-seconds 120
python -m backend.modules.host_node.control_cli stop asr --wait-seconds 300
python -m backend.modules.host_node.control_cli upgrade asr --version v2 --wait-seconds 300
```

客户端只调用 Node API，先核对 Node ID，读取配置/控制版本后提交一次操作；不直连 Docker。可用 `--env-file`、`--node-url`（回环 HTTP 或可信 HTTPS）、`--operation-id` 恢复查询已知操作。POST 结果不明时核对原 operationId，不换编号重发。

CLI 输出 JSON 操作编号、阶段和状态；成功/已安全回退返回 0，未知/受阻/失败返回 2，受理但等待尚未结束返回 3。等待超时不取消操作，也不代表容器已经停止；rolled_back 保留请求版本与实际回退版本，不能当作升级到新版本成功。

对应 API 为 POST `/node/v1/services/{id}/operations`，管理凭据，字段为 `operationId`（UUID）、`action`（start/stop/upgrade）、`versionId`、`expectedControlVersion` 和 `configRevision`。停止不传目标版本。受理返回 202，此时只保存控制记录，后台才执行。

## 控制规则

1. 接到操作即关闭 Node 新提交门禁，固定服务与运行修订，保存事件。
2. 先核对登记容器的完整身份、镜像、标签和状态；不接管其他运行容器。启动一个已由本 Node 管理且正在运行的同版本，只核对状态，不重复调用 start。
3. 停止/升级调用业务 drain，等待**关联本次操作和当前实例的新报告**：不接单、内部排队=0、运行=0。HTTP ACK 或旧的空队列报告都不够。
4. 只发 SIGTERM，另行 inspect 确认退出；超时进入 blocked，不升级为 SIGKILL。Docker 常规 stop 有超时强杀行为，首版不使用它。[Docker 信号说明](https://docs.docker.com/reference/cli/docker/container/kill/)
5. 升级在旧容器退出后绑定新实例、启动候选、等待就绪，再调用 resume 并等待关联的新接单报告，最后打开门禁。
6. 自动回退必须明确启用、兼容依据齐全，新实例没有进入恢复接单阶段、从未报告接单/任务活动，且当前新鲜报告明确内部队列与运行均为零。缺报告、历史接过任务、恢复结果未知或队列未知均不自动回退。
7. 回退也先确认候选退出，再为旧版本生成新实例并走预热/恢复，最终状态为 rolled_back，保留原升级历史。

CPU/GPU 指标、心跳过期、查询404或命令超时不作为排空、退出或推理终态依据。服务没有 drain/resume 时可声明无此能力，记录 BUSINESS_DRAIN_UNSUPPORTED 并阻止运行容器的停止/升级，不自行修改对方服务。

## 查询、恢复与日志

| 接口 | 权限与作用 |
|---|---|
| GET `/node/v1/services/{id}/operations` | 管理/只读；page/pageSize 分页，默认20、最多100 |
| GET `/node/v1/operations/{operationId}` | 管理/只读；本地阶段和错误码 |
| POST `/node/v1/operations/{operationId}/reconcile` | 管理；提供 expectedControlVersion，显式观察核对后恢复安全阶段 |
| POST `/node/v1/operations/{operationId}/abort` | 管理；全部容器确认停止、人工核实全部未决控制命令已结束后，终结未知/受阻操作 |
| GET `/node/internal/v1/services/{id}/assignment` | 对应业务凭据；取得当前实例、修订、代次、当前操作和 startPaused |
| GET `/node/v1/resources` | 管理/只读；只读资源快照 |

Docker/HTTP 动作前先保存 issued 阶段，事务外调用。回复丢失、进程中断、数据库落结果失败均不会自动重发该动作；reconcile 先核对事实，仅在足以确认的阶段继续。Node 重启把未决操作标为 unknown、关闭门禁，并后台核对已有容器，不重复启动/停止。

abort 要求 `expectedControlVersion` 和至少16字符 evidence，只保存证据摘要；容器状态查询失败或仍有运行容器时拒绝。此操作不强制停止容器，不结束平台推理任务、不释放中心未知容量，完成后接单门禁仍关闭。人工证据必须覆盖未决 Docker **及业务**命令，不可仅凭一次快照推断全部命令结束。

关键阶段、实例、容器观测和错误变化写入原 Node 事件；普通重复观察不刷事件。命令参数、上报凭据、原始 inspect（含环境秘密）、HTTP 响应和人工核对正文不写运行日志。原日志继续按进程滚动。

## 资源指标

默认后台每五秒采样，页面只读持久快照。CPU 采用两次计数差，首次为 warming、百分比 null；内存显示物理总量、可用量、已用量及比例。Linux MemAvailable 不等于 MemFree；不把缓存简单认作不可用内存。

NVIDIA GPU 显示索引/UUID、名称、总显存、已用显存、利用率。N/A 为 null；工具缺失、超时、格式异常、空响应分别标记错误，不推断没有 GPU 或 GPU 空闲。[NVIDIA 查询格式与兼容性说明](https://docs.nvidia.com/deploy/nvidia-smi/index.html)

失败保留上次可信值和 lastSuccessAt，显示本次 checkedAt/errorCode/fresh=false。满十五秒或 Node 启动代次变化后失效，CPU 预热样本不标为有效利用率。当前 GPU 适配面向物理 NVIDIA 设备，其他设备或不兼容输出显示不可用；这不是实际任务设备证据或并发容量依据。
