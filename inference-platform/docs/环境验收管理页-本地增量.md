# 环境与待验收记录：本地管理页增量

本轮继续本地开发，把已经落盘的验收问题接到管理页面。**这是6B的本地展示增量，不代表真实Redis、Linux或模型验收完成，也不自动进入6C。** 不再尝试校园网连接，不安装依赖，不改变日常任务或数据库结构。

## 页面怎么用

打开左侧“应用与任务监控”，查看“环境与待验收记录”：

1. 可按6A部署准备、6B Redis验证筛选，默认每页50条。
2. “待外部验收”单独显示，原因使用直白说明，例如“校园网暂不可达，真实联调待网络恢复”。它不会计作任务失败或服务已停止。
3. 查看记录来源（人工确认/平台检查）、首次/最近记录时间、观察次数和证据哈希。不会提供原SSH响应、密钥或证据文件下载。
4. “刷新验收记录”只读取本地已保存的快照，不执行SSH、Redis、Node核对、调度或推理。没有自动轮询。
5. 没记录不等于通过；损坏记录、扫描不完整、请求失败都会提示未确认。手动刷新失败时保留上一份已读取记录并明确标注；筛选改变时丢弃旧请求的过时响应。

即使公共调用关闭、数据库仍是0014，也可以使用这个面板，不要求先升级公共任务管理表。若后台进程仍运行旧代码，需要在**下次正常重启**时加载新接口；本轮不为页面中断日常API/Vite，也不迁移数据库。旧后台返回404时页面会明确提示接口尚未加载。

当前管理页只展示中心平台本地的验收问题快照。Node任务进度、实际设备和任务时间线仍走已有监控，不混在这些环境问题里；本轮没有增加远程日志采集或修改其他主机服务。

## 配置与记录位置

后台从当前`INFERENCE_LOG_DIR`的`validation/`子目录读快照。默认即`runtime/logs/validation/`，兼容此前已登记的校园网问题。后台自定义日志路径时，CLI需显式指定同一目录；CLI仍不隐式读取日常.env：

```sh
python -m backend.modules.deployment.validation_log --log-dir /absolute/center-logs/validation defer --stage module6b --target lab-node --code CAMPUS_NETWORK_UNAVAILABLE --source operator
```

省略`--log-dir`仍沿用原默认目录。目录不可读或错误配置不会阻止平台启动，查看时返回受控错误。平台GET不创建验收目录、不追加观察次数或更新快照；普通HTTP访问日志仍按已有规则记录。

## 本机只读接口

```text
GET /api/admin/validation/issues?stage=module6b&offset=0&limit=50
GET /api/admin/validation/openapi.json
```

`stage`可省略；`offset`默认0、允许0—1000，`limit`默认50、最多200。未知参数和重复参数拒绝。接口只有GET，沿用本机地址/Host/Origin/Sec-Fetch-Site检查，应用API Key不能绕过远程限制；不加入Node对外白名单。返回`Cache-Control: no-store`。

响应包含`items/total/offset/limit/unreadableCount/scanTruncated/notice`。每项只返回阶段、目标别名、受控原因代码、来源、待验收状态、时间、观察次数和证据哈希；不返回本机绝对路径、证据相对路径、原日志正文或连接配置。

每次最多扫描1000个目录条目，仅接受匹配身份文件名的快照，单份上限8KiB；损坏/过大/身份不符的快照不展示，返回不可读数量。达到扫描上限时`total`只是本次已读取有效记录的数量，`scanTruncated=true`，页面明确提示并非完整清单。分页按最近观察时间倒序，相同时间按阶段/目标稳定排序；本地快照可能在两次请求之间变化，不是固定历史快照游标。

OpenAPI保存为[validation-issues.openapi.json](validation-issues.openapi.json)，与代码生成结果一致。现有应用侧`/api/v1`协议不变。
