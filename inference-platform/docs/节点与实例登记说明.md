# 本机节点与ASR实例登记说明

ASR-2A在现有后台增加三类持久化档案：**节点是这台电脑；实例是这台电脑上固定配置的一个ASR执行位置；会话观测是一次真实Worker运行所留下的报告。**本部分的当前实现和实际验收见[阶段记录](阶段记录/ASR-2A-节点与实例登记-验收记录.md)。

登记不会启动模型，也不会授予进程控制权。ASR-2A交付时只有原五服务和显式观测；当前ASR-2B已交付独立Agent管理的开发侧及真实验证，具体运行方法见[ASR独立启停说明](ASR独立启停说明.md)。本说明中的旧Worker观测来源和历史保持，不改称受管启动证据。

## 1. 数据与身份

| 档案 | 保存内容 | 不能据此推定的事情 |
|---|---|---|
| `compute_nodes` | 稳定节点ID、内部本机身份哈希、主机名、Windows版本、架构、逻辑处理器数及登记/采集时间 | CPU可分配容量、GPU资源或Agent在线 |
| `service_instances` | 稳定实例ID、节点、固定`asr-default`、准确模型版本、适配器与CPU配置 | 已启动、已加载模型或已经能接任务 |
| `instance_sessions` | 来自已有Worker的实际会话ID、PID/child PID、报告状态、心跳、任务及错误摘要 | 对PID的操作授权、实时进程存活或确认退出 |

本机身份从Windows的MachineGuid读取后加命名空间哈希，原值不保存进这些档案，也不通过HTTP输出；主机名只作展示，不用于稳定身份。同一Windows环境重复登记复用同一节点及实例，登记时间保留，元信息采集时间可以更新。登记失败不回退为随机机器身份。

本阶段只接受当前Windows本机和一个CPU ASR实例。把已登记的数据库复制到另一台电脑后不能直接再次绑定第二个节点；系统重装、克隆机器或迁移身份的处理须另行核查，不通过手工改库绕过冲突。`cpuCount`是操作系统报告的逻辑处理器数量，不代表空闲核数；`gpuStatus=not_probed`明确表示未探测，不能解释为“无GPU”或“GPU空闲”。

实例绑定既有Whisper small准确版本及`faster-whisper`适配器，原模型版本不被覆盖。启用/禁用模型仍走[模型管理说明](模型管理说明.md)中的既有流程；登记不会下载模型、加载权重或更改模型可用性。

## 2. 登记与只读查询

在开发目录使用现有环境。旧数据库应先停止相关服务，成对备份数据库与上传目录，再按[迁移说明](../migrations/README.md)升级至最新版本；应用不会自动迁移。

```powershell
Set-Location -LiteralPath 'D:\1 研究生\aixm\inference-platform'
$projectPython = 'C:\Users\86199\miniconda3\envs\project311\python.exe'
& $projectPython -m backend.modules.nodes.node_registry register-local
& $projectPython -m backend.modules.nodes.node_registry list-nodes
& $projectPython -m backend.modules.nodes.node_registry list-instances
```

`register-local`只从当前机器和既有模型登记读取数据，没有可指定机器地址、模型路径、PID或任意命令的参数。成功输出`node`、`instance`、`nodeCreated`、`instanceCreated`；重复执行两个created字段为false。若之后测试生成了真实会话，重复登记也不会清空它。

查询不需要先启动API。通过CLI输出中的`instanceId`查询会话：

```powershell
$instanceId = '将此处替换为list-instances输出的32位instanceId'
& $projectPython -m backend.modules.nodes.node_registry list-sessions --instance-id $instanceId
```

列表均支持`--page`（默认1）与`--page-size`（默认20，上限100）；实例列表另支持`--node-id`。成功命令在标准输出给出camelCase JSON，失败给出统一错误JSON，日志位于配置日志目录的`node-registry.log`。CLI成功退出码0，已知校验/业务错误为2；参数解析错误也不会执行登记。

API启动后还可使用5个只读接口：`GET /api/nodes`、`GET /api/nodes/{nodeId}`、`GET /api/instances`、`GET /api/instances/{instanceId}`、`GET /api/instances/{instanceId}/sessions`。完整字段、分页和错误见[接口说明](接口说明.md)。这些GET不会自动登记机器、采样报告或启动Worker；本部分没有登记/启停的写入HTTP接口。

## 3. 显式保存真实Worker会话观测

以下命令仅用于尚未由Agent托管的旧Worker观测；当前实例进入Agent管理后会拒绝继续归档，需改查 `/management/sessions` 的受管历史，避免混淆来源。仅旧模式确实需要保留一次报告时执行：

```powershell
& $projectPython -m backend.modules.nodes.node_registry observe-local
```

该命令不会启动Worker，也不会检查或终止报告里的PID。它读取当前数据库已有的ASR `runtime_components.worker`报告，在本机登记及模型绑定吻合时保存观测。为了避免把旧数据中的历史Worker冒充新实例启动，早于本次实例登记的启动报告返回`pre_registration_report`，不建立会话；没有报告返回`no_worker_report`。这两种情况均属于没有可归档的新会话，并非进程管理操作失败。如果登记时Worker已经在运行，其启动时间也早于实例登记；需要本轮会话观测时，先等待或按原规则处理当前任务，再使用原整个平台停止/启动脚本完成一轮启停，之后执行`observe-local`。不要直接操作报告中的PID，也不要把此步骤理解为已经支持独立ASR启停。

同一Worker会话只保留一条最新已采样报告。心跳时间和报告字段全部相同返回`unchanged`，迟到的较旧报告返回`older_report`，新报告插入或更新后返回`recorded`；同一数据库毫秒内从idle变为stopped也会保留字段变化。同一会话的PID或启动时间变化会拒绝；报告时间在未来或启动时间晚于心跳也会拒绝。Worker真实再次启动后具有新会话，旧记录仍可分页查询。

这不是持续采样服务。Worker可持续更新原`/api/runtime`，新档案只在手动执行`observe-local`时更新；两者在查询时不同并不一定是故障。GET不会悄悄延长档案新鲜度。

## 4. 怎样理解状态

- 节点的`registrationState=registered`表示已登记。旧档案字段属于ASR-2A观测契约；Agent当前在线和就绪状态以新的管理查询为准，不从登记状态推断。
- 实例固定绑定与旧 `latestObservation` 保持可读。旧观测的 `runtimeState=unknown` 不据历史报告自动声称正在运行；受管状态、意图和退出确认由ASR-2B的管理查询提供。
- 实例详情的`latestObservation`可能为null，表示尚无符合条件的已采样会话。会话中的`reportedState`、`reportedModelReady`是报告内容，不是本次主动健康检查。
- `freshness=fresh`只表示最新已采样心跳尚在有效窗口内；`stale`表示过期；`superseded`表示已有更新的启动会话；`clock_skew`表示查询时发现时钟异常。新鲜度用数据库当前时间计算，不因反复查询而刷新心跳。
- 即使`reportedState=stopped`，`exitConfirmed`仍为false。本部分没有进程管理权或退出证明链路；过期、断联、旧PID和停止报告都不能替代实际退出确认。

## 5. 常见提示及后续

| 提示 | 处理方向 |
|---|---|
| `NODE_REGISTRY_UNAVAILABLE` | 确认数据库可访问，已备份并执行当前Alembic迁移 |
| `NODE_PROBE_FAILED` | 核对当前是否为Windows以及本机身份读取权限；不填写伪造机器信息 |
| `MODEL_VERSION_NOT_FOUND` / `INSTANCE_BINDING_CONFLICT` | 核对已有Whisper准确规范；不要覆盖旧实例版本来消除错误 |
| `LOCAL_NODE_CONFLICT` | 数据库已属于另一台机器，先核查数据迁移与身份，当前阶段不支持第二节点 |
| `LOCAL_NODE_NOT_REGISTERED` / `LOCAL_INSTANCE_NOT_REGISTERED` | 先在本机执行`register-local` |
| `INVALID_WORKER_REPORT` / `WORKER_SESSION_CONFLICT` | 保留异常报告并核查时间和会话来源，不通过改PID或改库伪造有效状态 |
