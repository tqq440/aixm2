## 2. 后端三级目录

普通后端代码文件必须使用 `backend/<层级>/<领域或分类>/<文件名>.py`。按当前阶段需要建立分类，不提前生成全部模块空壳。

| 层级 | 放什么 | 后续路径示例 |
|---|---|---|
| utils | 无业务规则的工具 | `backend/utils/date/time_utils.py` |
| common | 公共异常、日志、安全组件 | `backend/common/exceptions/app_error.py` |
| data | SQLAlchemy模型与持久化操作 | `backend/data/task/task_repository.py` |
| schema | Pydantic输入输出校验和字段映射 | `backend/schema/task/task_schema.py` |
| service | 任务、租约、转写、投递等业务规则 | `backend/service/task/task_service.py` |
| controller | Flask路由与请求响应衔接 | `backend/controller/v1/task_controller.py` |
| modules | Worker、投递器和应用运行组织 | `backend/modules/worker/asr_worker.py` |
| config | 集中的配置读取 | `backend/config/settings/app_settings.py` |

以上是目录命名示例，不作为实现状态清单；实际实现以代码和开发进度为准。包标记文件按Python包实际需要设置，不在标记文件中堆业务逻辑。

### 职责和依赖

```text
HTTP入口 controller ─┐
                    ├─> service ─> data/common ─> utils
后台入口 modules ───┘
```

modules组织循环、启动和停止；service决定任务能否执行、是否重试、租约是否有效。data不反向依赖service，utils不依赖其他项目层，禁止循环依赖。Controller和Modules复用Service，不能各写一套任务逻辑。

业务架构M01—M15是职责标识，不要求创建15个独立服务或15个modules子目录。M08投递规则、M12执行规则按职责分层，保留函数与架构编号映射。

## 4. 编码与数据要求

- 先检索工具与公共组件再新增代码，使用绝对导入。
- 外部输入经Pydantic校验；接口字段使用camelCase，内部使用snake_case，在Schema转换。
- SQLAlchemy表名用复数snake_case，ORM提供to_dict；列表查询分页，避免N+1查询。
